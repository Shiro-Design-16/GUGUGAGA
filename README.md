# 咕咕嘎嘎语（GUGUGAGA）
**语言**：中文 ｜ [日本語](README.ja.md) ｜ [English](README.en.md)

> 一门只用 `咕` `嘎` `！` `？` `：` 空格 换行 缩进 写成的纯 OOP 语言。
> 源码里没有字母、没有数字、没有字符串、没有注释——一切名字都是 `咕`/`嘎` 的位串，一切输出都是位流。

**现状**：v1 已跑通。419 条测试全绿（语言 142 + 翻译器 104 + 扩展 173），7 个示例程序可执行，零运行时依赖（Node 24 的类型剥离直接跑 `.ts`）。

---

## 0. 它是什么，不是什么

**是**：一门有类、继承、字段、方法、构造器、`自己`（this）、动态派发、静态入口块、局部作用域、`当`/`如果`/`返回`、步数与深度限制的静态检查型解释语言。它比 Brainfuck 高一个抽象层级——你能在里面写「类」，而不是只能写纸带操作。

**不是**：
- 不是给真实工程用的（性能非目标，纯树遍历解释器）。
- 没有字符串、没有数组、没有异常、没有泛型、没有注释。
- **不输出人类可读文本**。程序只能写裸位流；想看见「嗨」，需要另一个项目——**咕嘎翻译器**（编码约定见 §4）。

## 1. 快速开始

```bash
./install.sh            # 装一次：把 咕咕嘎嘎 / ググガガ / gggg / gg / ggt 链接到 PATH 上的目录
gggg examples/咕嘎咕嘎.咕咕     # 像 python x.py 一样直接跑；stdout = 24 位裸位流 = E5 97 A8 = 「嗨」
咕咕嘎嘎 嘎嘎 examples/嘎嘎咕咕.咕咕  # 只做词法/语法/静态检查，成功则完全静默
printf 35 | gggg examples/咕嘎嘎咕.咕咕
./demos/咕咕咕嘎.咕咕     # 首行 #! 的 .咕咕 文件本身就是可执行脚本
npm test                # node --test "tests/**/*.test.ts"
```

不装也能跑：`./bin/gg.ts examples/咕嘎咕嘎.咕咕`。装法有三条，任选：`./install.sh`（推荐，五个命令一次到位、软链回本仓库，改代码立刻生效）、`npm link`（根目录链接 `咕咕嘎嘎`/`ググガガ`/`gggg`/`gg`，`translator/` 里再 `npm link` 得到 `ggt`）、或自己把 `bin/gg.ts` 软链成任何你喜欢的名字。

源码文件后缀有四个（大小写不敏感）：`.咕咕`、`.ググ`、`.gu`、`.gugugaga`。文件名与示例名都已改成纯位名（`examples/咕嘎咕嘎.咕咕`、`examples/ガググガグ.ググ`、`examples/gugugaga.gu`）；目录名仍是 ASCII（`src/`、`tests/`），那是宿主工具链的骨架，不参与语言。

**报错也是位流。** 出错时 stderr 上只有 `咕`/`嘎` 的诊断帧，一行字都没有——给人看的文案由翻译器还原：

```bash
咕咕嘎嘎 程序.咕咕 2> /tmp/咕 || ggt decode --diag /tmp/咕
# 2:7 E1001 非法字符“噶”（U+5676）
```

细节见 §11 与 `SPEC.md` §12（GGDIAG v1）。`gggg 文件.咕咕` 会省略 `run` 子命令：第一个非选项参数带上面那四个后缀之一（或是一个已存在的文件）时，就按执行处理。

## 2. 字符集：为什么刚好是这八个符号

八个符号，三套写法（方言），逐位置等价——同一份文件、同一个词里都能混用：

| 位 | 中文（默认） | 日语 | 英语（大小写不敏感） |
| --- | --- | --- | --- |
| 0 | `咕` U+5495 | `グ` U+30B0，兼容 `ぐ` U+3050 | `GU`：`Gu`/`gU`/`gu` 都算 |
| 1 | `嘎` U+560E | `ガ` U+30AC，兼容 `が` U+304C | `GA`：`Ga`/`gA`/`ga` 都算 |

标点与空白同样等价：`！`=`!`、`？`=`?`、`：`=`:`；缩进用半角空格 U+0020 或全角空格 U+3000 都行，各算一格。词法器逐位置归一化成 `咕`/`嘎`，其后的词法/语法/语义只面对中文位串。

| 记号 | 码点 | 用途 |
| --- | --- | --- |
| `咕` | U+5495 | 位 0；同时用作「打印」的裸词 |
| `嘎` | U+560E | 位 1 |
| `！` | U+FF01 | 全角叹号：定义后缀 / 调用后缀 |
| `？` | U+FF1F | 全角问号：取值后缀 |
| `：` | U+FF1A | 全角冒号：一段的后缀边界（块头、绑定、实参、返回……） |
| 空格 | U+0020 | **只**用于分隔同一行内的记号 |
| 换行 | U+000A | 语句终止符 |
| 缩进 | 4 个空格起步 | 块结构 |

八条硬规则：
1. 标点全角半角**都合法**（`！`=`!`、`？`=`?`、`：`=`:`），中文方言默认写全角。真正非法的是不在字符集里的字符。
2. 缩进**只用空格**（半角 U+0020 或全角 U+3000，各算一格，一个块里混用也行），且必须最外层 0 缩进、块内一致增加。制表符 Tab 是 E1001。
3. 读取时 CRLF 归一为 LF；BOM 不合法。
4. **没有注释语法**——注释会引入第九个符号，破坏「只用这八个符号」的前提。
5. **没有字符串**。字符串 = 位串字面量，约定 UTF-8 逐字节 8 位（§4）。
6. **没有数字**。整数 = 二进制位串，写作 `嘎嘎嘎？` 紧贴若干位。
7. 只有位名参与编码（`咕`/`グ`/`GU`、`嘎`/`ガ`/`GA`）。**注意：`噶`（U+5676）、`呷` 等长得像的字都不合法**，会被 E1001 拦下并报出码点；英文的 `g`/`G` 必须凑成 `GU`/`GA` 两位，落单也是 E1001。
8. 唯一 I/O：出 = `咕：<表达式>` 写裸位流到 stdout；入 = `嘎嘎嘎嘎嘎嘎嘎`（读入）从 stdin 读 UTF-8 的下一个字节（0..255），EOF 返回空。

## 3. 语言速览

> 本章的表一律用中文方言写（`咕`/`嘎`）；其他方言按 §2 的对照表逐位置替换即可，例如 `咕咕！` = `ググ！` = `GUGU!`。匹配发生在归一化之后，方言不影响任何一条。

### 3.1 保留词（21 个）与保留记号（30 个）

**裸词（无后缀，7 个）**

| 写法 | 含义 | Java |
| --- | --- | --- |
| `咕` | 打印（后面跟 `：表达式`） | `System.out.write` |
| `嘎嘎` | 返回 | `return` |
| `嘎嘎嘎` | 如果 | `if` |
| `嘎嘎嘎嘎` | 否则 | `else` |
| `嘎嘎嘎嘎嘎` | 当 | `while` |
| `嘎嘎嘎嘎嘎嘎` | 自己 | `this` |
| `嘎嘎嘎嘎嘎嘎嘎` | 读入 | 读 stdin 一个字节 |

**声明词（后缀 `！`，4 个）**：`咕咕！` 定义类 ｜ `咕咕嘎！` 定义方法 ｜ `咕咕嘎嘎！` 程序入口 ｜ `咕嘎嘎！` 新建实例

**动作词（后缀 `！？`，2 个）**：`咕咕！？` 绑定（赋值 / 声明字段） ｜ `咕嘎！？` 求值并丢弃

**取值词（后缀 `？`，17 个）**

| 写法 | 名称 |
| --- | --- |
| `咕？` | 加（整数相加；两个位串 = 拼接） |
| `咕咕？` | 减 |
| `咕嘎？` | 乘 |
| `咕咕咕？` | 除（向零截断） |
| `咕咕嘎？` | 取余 |
| `咕嘎咕？` | 相等 |
| `咕嘎嘎？` | 小于 |
| `咕嘎嘎咕？` | 大于 |
| `咕嘎咕咕？` | 与（不短路） |
| `咕嘎咕嘎？` | 或（不短路） |
| `咕咕咕咕？` | 非（一元） |
| `咕咕嘎咕？` | 负（一元） |
| `嘎嘎嘎？<位串>` | 整数字面量（无符号二进制，前导 0 可省） |
| `嘎嘎嘎嘎？<位串>` | 位串字面量（长度随意，不做 8 位对齐校验） |
| `嘎嘎？` | 真 |
| `嘎嘎咕？` | 假 |
| `嘎咕？` | 空 |

读数写法：`<名字>？`。运算符一律**前缀式**：`咕？ a b` = `a + b`。没有括号，所以只能前缀——这是唯一无歧义的选择（§7）。

### 3.2 语法糖一览

| 写法 | 含义 |
| --- | --- |
| `咕咕！ <名字>` + 缩进块 | 定义类 |
| `咕咕！ <子类>：<父类>？` + 缩进块 | 继承 |
| `咕咕！？ <名字>：<表达式>` | 类体里 = 声明字段；语句里 = 赋值 / 新建局部 |
| `咕咕嘎！ <方法名> [：<参数名>]*` + 缩进块 | 定义方法；**方法名与类名相同即构造器** |
| `咕咕嘎嘎！ <名字>` + 缩进块 | 程序入口（静态上下文，没有「自己」） |
| `咕嘎嘎！ <类名>？ [：<实参>]*` | 新建实例 |
| `<接收者> <方法名>！ [：<实参>]*` | 调用方法 |
| `<对象>？ <字段名>` | 读字段 |
| `咕咕！？ <对象>？ <字段名>：<表达式>` | 写字段 |
| 行末只剩一个 `：` | 语法糖：该行等价空行，便于视觉对齐 |

### 3.3 一个完整程序（真的能跑）

类 `咕咕咕嘎`：两个字段 `嘎`=3、`嘎咕咕`=2；方法 `嘎嘎嘎咕` 返回两者之和；入口 new 一个实例并打印（64 位，值 5）。

```text
咕咕！ 咕咕咕嘎：
    咕咕！？ 嘎：嘎嘎嘎？嘎嘎
    咕咕！？ 嘎咕咕：嘎嘎嘎？嘎咕
    咕咕嘎！ 嘎嘎嘎咕：
        嘎嘎：咕？ 嘎？ 嘎咕咕？
咕咕嘎嘎！ 咕嘎嘎嘎：
    咕咕！？ 嘎咕嘎：咕嘎嘎！ 咕咕咕嘎？
    咕：嘎咕嘎？ 嘎嘎嘎咕！
```

实测输出 64 位、低三位 `嘎咕嘎`，解码为 5。

### 3.4 与你最初那份假设草稿的对照

你给的骨架（`咕咕！ 咕嘎：` 定义类、`咕咕！？ 咕：` 声明变量、`咕咕嘎！ 咕咕嘎：` 定义方法、`嘎嘎：` 返回、`咕咕嘎嘎！` 入口、`咕嘎嘎！` 实例化、`咕嘎！？` 调用）基本都保留了，但有几处必须修正：

1. 草稿里的 `噶`（U+5676）不是合法字符——只有 `咕`/`嘎`。于是字段/方法名必须从**未被保留词占用的位串**里取（§5），`咕`、`咕嘎` 这类短名字都被关键字占了。
2. 读数必须带 `？` 后缀：写 `咕` 是打印语句，写 `咕？` 才是「读出名字 `咕` 的值」。没有这个后缀，`咕`/`嘎嘎`/`嘎嘎嘎` 就会和关键字撞车。
3. 方法调用写成 `<接收者> <方法名>！`；`咕嘎！？` 是「求值并丢弃」，用于整个表达式的副作用。
4. 草稿里 `嘎嘎： 咕？ 咕咕嘎 嘎？` 若意为「返回 变量咕 + 变量嘎」，应写 `嘎嘎：咕？ 咕？ 嘎？`（前缀式：运算符吃掉紧随的两个表达式）。

### 3.5 一条容易踩的语法边界

`新建`（`咕嘎嘎！`）可以出现在**任何表达式起点**：绑定右值、二元运算右操作数、冒号之后的实参槽、字段初始化值；但它**不能紧跟在一个已结束的表达式后面**（前缀式文法没有括号，那种场合先绑局部变量）。实参的唯一分隔依据是冒号，所以 `m！：a：b` 是 2 个实参，而 `m！：a 咕嘎嘎！ C？` 仍是 1 个实参。

## 4. 输出编码约定（咕嘎翻译器的接口）

stdout 是**连续裸位流**：只有位名 0 与 1，**没有分隔符、没有换行、没有结尾换行**。位名画成哪套字形跟源文件后缀走（见 §10 与 `SPEC.md` §8.1）：`.咕咕` → `咕`/`嘎`，`.ググ` → `グ`/`ガ`，`.gu`/`.gugugaga` → `GU`/`GA`。

| 值类型 | 输出位宽 | 说明 |
| --- | --- | --- |
| 整数 | **定长 64 位**补码，高位在前 | 超出 64 位取低 64 位 |
| 位串 | 原样，逐位照抄 | 长度即字面量长度 |
| 布尔 | **8 位**：假 = 8 个 `咕`，真 = 8 个 `嘎` | 与字节对齐 |
| 空 / 对象 | — | E4006，不可输出 |

**字符串约定**：用位串表示，按 UTF-8 逐字节 8 位、高位在前、字节依次输出（保持 8 位对齐）。出错的位移之前的输出**保留**在 stdout 上（流式，不缓冲）。

翻译器的职责据此完全确定：读 stdin 的位流 → 按约定切分 → 打印人类可读文本。**这条约定就是本项目与 `translator/` 之间唯一的契约。**

## 5. 名字经济学：为什么变量会叫「嘎咕嘎」

名字 = 至少一位的 `咕`/`嘎` 串，且不得等于保留词。于是可用名字空间被切得很碎：

| 名字长度 | 可用个数 | 例子 |
| --- | --- | --- |
| 1 | 1 | `嘎` |
| 2 | **0** | —（`咕咕` `咕嘎` 都被占了） |
| 3 | 2 | `嘎咕咕` `嘎咕嘎` |
| 4 | 9 | `咕咕咕嘎` `嘎嘎嘎咕` … |
| 5 | 31 | |
| 6 | 63 | |
| 7 | 127 | |

这就是示例里名字偏长的原因——短名字基本被关键字吃光。`docs/名字对照表.md` 逐行把每个示例的位串翻译成人话，并对应到 Java 概念。

## 6. 与 Java 的对应

| Java | 咕咕嘎嘎语 |
| --- | --- |
| `class C { }` | `咕咕！ C：` + 缩进块 |
| `class D extends C` | `咕咕！ D：C？` + 缩进块 |
| 字段声明 | `咕咕！？ 字段名：初值`（类体内；按祖先到子类顺序初始化） |
| 方法 | `咕咕嘎！ 名字 [：参数]*` + 缩进块 |
| 构造器 | 名字与类名相同的方法；`新建 C：a：b` 按实参个数匹配 |
| `this` | `嘎嘎嘎嘎嘎嘎`（自己） |
| `new C(...)` | `咕嘎嘎！ C？ [：实参]*` |

| `System.out.write(b)` | `咕：<表达式>` |
| 异常 | 无（错误即终止，退出码见 §10） |

## 7. 设计取舍：几条关键路线选择

1. **行式语法 + 缩进块**，而不是「一行一大串位流」。要「看起来像一门独立语言」就必须有可读结构；在只有这八个符号的前提下，缩进是唯一能表达块结构的办法（没有括号、没有分号）。
2. **后缀编码记号种类**：裸词 = 语句/关键字，`！` = 声明/调用，`！？` = 动作，`？` = 取值，`：` = 段边界。这样关键字与用户名字不冲突，且**最长匹配可判定**——词法器只看「位串后紧跟哪个后缀」就能定记号种类。
3. **表达式一律前缀式**。没有括号 ⇒ 中缀无法分组（`a+b*c` 无解）。代价是嵌套实参要先用局部变量接住（§8）。
4. **静态检查 + 树遍历解释器**，不做 AST 优化、字节码、JIT：性能非目标，可读性优先（`src/interp.ts` 一个文件说清全部语义）。
5. **输出 = 裸位流**，语言层不做「打印字符串」。一旦允许人类可读输出，字符集就得再塞进几十个符号，整个设计前提就破了。可读性交给翻译器。
6. **没有注释语法**：加注释就得引入第九个符号。

## 8. 已知缺口（v1 非目标，写下来不装作没有）

- 没有括号 ⇒ 嵌套调用 `f(g())` 必须拆成中间变量；`新建` 不能紧跟已结束的表达式（§3.5）。
- 没有字符串 / 数组 / 集合类型；字符串只是位串约定。
- 没有不等运算符，也没有小于等于/大于等于；用 `与` + `非` + `相等` 组合。
- 没有注释。
- 空位串写不出来（`嘎嘎嘎嘎？` 后面必须紧贴至少一位）。
- 只有一层 I/O：stdout 位流 + stdin 字节；没有文件、没有网络。
- 没有异常/捕获；运行期错误即终止（已写出的位保留）。
- 短名字稀缺（§5）。

## 10. CLI 参考

```text
用法：
  咕咕嘎嘎 <文件>                             # 执行，裸位流写 stdout（省略动作词，像 python x.py）
                                              # 后缀：.咕咕 / .ググ / .gu / .gugugaga（大小写不敏感）
  咕咕嘎嘎 嘎 <文件>.咕咕                     # 同上，显式写法
  咕咕嘎嘎 嘎嘎 <文件>.咕咕                   # 只做词法/语法/静态检查，成功静默
  咕咕嘎嘎 嘎嘎嘎                             # 帮助（帮助正文是一帧，走 stderr）
  咕咕嘎嘎 嘎嘎嘎嘎 <咕嘎位串> <文件>.咕咕     # 设步数上限（位串按二进制读）
退出码：0 成功；1 运行时错误；2 词法/语法/静态错误；3 用法错误
```

动作词本身就是这门语言的字：`嘎`=执行、`嘎嘎`=检查、`嘎嘎嘎`=帮助、`嘎嘎嘎嘎`=步数上限。拉丁别名 `run`/`check`/`--help`/`--max-steps N` 只为人手旧习惯保留，**不属于语言词汇**。

命令名 `咕咕嘎嘎`（与日语 `ググガガ`、`gggg`、`gg` 同一入口）；没装时等价写法是 `node bin/gg.ts ...`。文件后缀四个都认，语言方言与后缀无关——`.咕咕` 里写 `GU` 一样跑。文件首行若以 `#!` 开头，执行/检查前会被跳过（替换为空行、行号不变），所以 `.咕咕` 文件能直接 `./程序.咕咕` 跑；`#` 出现在别的行仍是 E1001。

步数上限的位串：只含 `咕`/`嘎`，`咕`=0、`嘎`=1，高位在前——`嘎` 是 1、`嘎咕咕咕` 是 8、`嘎嘎嘎嘎嘎` 是 31。空串、含其它字符、或数值为 0 都算用法错误。

**输出字形跟随文件后缀**：程序位流与诊断帧用同一套位名，所以同一个程序的 stdout 与 stderr 永远同方言；帮助与命令行用法错误没有具体程序，恒定用中文 `咕`/`嘎`。

**所有诊断（含帮助与用法错误）都写 stderr**，stdout 只有程序的位流。所以 `咕咕嘎嘎 嘎嘎嘎 | less` 是空的；要看帮助得 `咕咕嘎嘎 嘎嘎嘎 2>&1 | ggt decode --diag`。

运行时约束：步数上限 **5 000 000**（语句执行、表达式节点求值各计 1 步；`嘎嘎嘎嘎` / `--max-steps` 可改），调用深度上限 **512**。stdin 是终端时按空输入处理，避免交互挂起。

### 11.1 诊断怎么读

错误码与位置都在 **GGDIAG v1 帧**里（`SPEC.md` §12）：stderr 上只有 `咕`/`嘎`，读不出字是正常的。交给翻译器：

```bash
咕咕嘎嘎 程序.咕咕 2> /tmp/咕 || ggt decode --diag /tmp/咕
# 2:7 E1001 非法字符“噶”（U+5676）
```

帮助帧（`咕咕嘎嘎 嘎嘎嘎`）同理。**位名字形跟随源文件后缀**：`.咕咕` 的帧是 `咕`/`嘎`，`.ググ` 是 `グ`/`ガ`，`.gu` 是 `GU`/`GA`；帮助与用法错误恒定中文。归一化后三种方言的帧逐位相同，`ggt decode --diag` 三套都吃。位名之外，人话文案仍然写在 `src/` 里，但它只是**被搬运的字节**——帧里带着原文的 UTF-8，所以翻译器不需要认识任何一条文案，也不用跟解释器同步改措辞。`ggt decode --diag` 输出的第一段是 `行:列`；没有位置的事件（读不到文件、用法错误）只有码名与说明。

## 13. 姊妹项目：咕嘎翻译器（已实现，见 `translator/`）

本仓库的语言侧职责到「裸位流 + 编码约定（§4）」为止；把位流变回人话由 `translator/` 负责（独立子项目：自己的 `package.json` / `README.md` / 104 项测试，零依赖，不 import 本仓库任何模块）。除了位流，它还负责把**诊断帧**翻译成人话（`ggt decode --diag`，见 §11）：

```bash
cd translator
../bin/gg.ts run ../examples/咕嘎咕嘎.咕咕 | node bin/ggt.ts decode --bytes   # 嗨
../bin/gg.ts run ../examples/咕嘎咕嘎.咕咕 | node bin/ggt.ts decode           # 嗨（stderr 说明猜到了 bytes）
printf 35 | ../bin/gg.ts run ../examples/咕嘎嘎咕.咕咕 | node bin/ggt.ts decode --plan plans/咕嘎嘎咕.plan  # 104 / -2
printf 嗨 | node bin/ggt.ts encode --as-literal    # 嘎嘎嘎嘎？+ 24 位，可直接粘进源码
```

解码模式：`--plan <文件>`（按槽位表精确解码）、`--int64`、`--bytes`（UTF-8 严格）、`--hex`、`--bits`；不给模式时按 64/8 的倍数猜，说明写 stderr。反向 `encode` 支持文本、`--int64` 十进制、`--as-literal`（生成位串/整数字面量）。两边都认三方言：`decode` 吃 `咕嘎`/`グガ`/`GUGA` 混写，`encode --ja` / `--en` 按方言输出位串（`--ja` 与 `--en` 互斥）。plan 是宿主层 ASCII 行式文件：`int64` / `bits <n>` / `bytes <n>` / `bool`。

为什么要 plan：位流不自描述，`64 位整数` 和 `3 个字节的位串` 在字节层面不可区分，所以「精确解释」必须由人给出槽位表；只想要个大概时用猜测模式。

根目录跑 `npm run test:all` 会连跑三方的测试（语言 142 + 翻译器 104 + 编辑器扩展 173 = 419 项）。

## 14. 编辑器支持：VS Code 扩展（`vscode/`）

光能跑不够，还得让人愿意在里面写。仓库里有一个零依赖的 VS Code 扩展：装一次之后 `.咕咕`、`.ググ`、`.gu`、`.gugugaga` 文件都有编辑器体验。

```bash
./vscode/build-vsix.sh                                   # 重新打包（仓库已带打好的包）
code --install-extension vscode/gugugaga-language.vsix    # 安装
```

装完打开任意上面四种后缀的文件，状态栏语言模式显示「咕咕嘎嘎语」，得到六样能力：

| 能力 | 表现 |
| --- | --- |
| 语言基础 | 四个后缀识别（`.咕咕`/`.ググ`/`.gu`/`.gugugaga`）、`：` 结尾自动缩进、`嘎嘎`/`嘎嘎嘎嘎`/`嘎嘎嘎嘎嘎嘎` 回退缩进、按缩进折叠、无注释语法 |
| 着色 | 30 个保留记号 + 整数/位串字面量（位串整段着色）+ 类名/方法名/变量名 + `！？`/`：` 标点，35 条 TextMate 规则，每条同时吃三方言（`咕\|グ\|ぐ\|[Gg][Uu]`）与半角标点 |
| 补全 | 按上下文（顶层 / 类体 / 语句位 / 表达式位 / 调用之后）给保留词与骨架片段；`！？` 之后只给本文档里已定义的方法名 |
| 悬停 | 记号释义、家族归属与用法示例——全部用 咕/嘎 写（外壳纯净，见下） |
| 诊断 | 打开 / 保存 / 编辑（防抖默认 350ms）时跑真实 `咕咕嘎嘎 嘎嘎`，解码 stderr 上的 GGDIAG 帧，把 `E1xx`~`E3xx` 变成波浪线与 Problems 面板条目 |
| 运行 | 编辑器标题栏的 ▶（以及右键菜单）把 `咕咕嘎嘎 <文件>` 发进集成终端，像 `python x.py` 那样；脏文档先存盘，终端复用，输出与退出码都留在终端里 |

运行按钮刻意**不接管输出**：位流的归处是终端，这样才能一边喂 stdin、一边把结果接给 `ggt decode`。它走隐式执行（不带动作词），参数拼装按平台加引号，不绑快捷键（命令面板里出现 ASCII 和弦会破坏外壳纯净度）。

外加 8 条片段（类、构造器、方法、入口、字段、条件、循环、新建表达式），正文除 咕/嘎/！/？/：/空格/换行 外没有别的字符。

设计上有三条值得记的取舍：

1. **诊断不是另写一个半吊子解析器**，而是调真的解释器：扩展 spawn `咕咕嘎嘎 嘎嘎 <文件>`，把 stderr 上的 GGDIAG 帧解回 `{行, 列, 码}`（`src/diagnostics.js` 自带零依赖解码器，不 import 仓库任何模块）。编辑器里显示的码与说明，与终端里解帧得到的完全一致。代价是依赖 CLI 可达：按「设置 `gugugaga.cliPath` → 工作区 `bin/gg.ts` → PATH 上的 `咕咕嘎嘎`/`ググガガ`/`gggg`/`gg`」三级回退找命令。
2. **外壳也是纯咕嘎**：设置页标题与描述、命令标题、输出面板、Problems 面板的来源列与条目正文（正文是该诊断的整帧位串，交给 `ggt decode --diag` 才成人话；码名列刻意留空，否则会渲染出 `E1001`）、补全候选说明、悬停文案、片段描述，全部只用 咕/嘎/！/？/：/空格/换行；`cliPath` 的默认值就是 `咕咕嘎嘎`，诊断集合名也是 `咕咕嘎嘎`。面板还有一道运行时闸：`isPureLine()` 不认的行不写面板、只进开发者控制台（`tests/purity.test.js` 用变异测试证明这道闸真的会拒）。排查信息（exec/args/工作区/栈）退到开发者控制台 —— 用户看不见，但也意味着「诊断为什么不出来」要开 DevTools 才能看全。清单里剩下的 ASCII 全是 VS Code schema 的匹配键（扩展 id、`scopeName`、命令 id、设置 id），改一个字符扩展就不加载。
3. **TextMate 禁用 lookbehind**，所以每条着色规则都吃掉一个左侧边界捕获组 `(^| +)` / `(^| +|：)` 再给捕获组上色。不这么做，类头规则会在调用名 `嘎咕咕嘎咕！` 的第 3 位匹配到 `咕咕！`、`咕咕？` 会在取值名里被当成减法 —— 这是整套语法里最关键的一处设计。

三个命令（运行当前文件 / 检查当前文件 / 显示输出面板）、五个设置（`cliPath`、`nodePath`、`checkOnChange`、`debounceMs`、`maxSteps`），结构与重新打包的说明见 `vscode/README.md`。

扩展自带 11 个测试文件、173 条断言，全部离线、零依赖、**禁** `require("vscode")`；其中 3 条会真 spawn `node bin/gg.ts 嘎嘎` 并把 stderr 的位流解回诊断（不是假绿）。因此本项目唯一没有实机验证的交付物就是它：配色、折叠手感、片段 Tab 跳转、悬停弹窗样式只有静态与离线证据，没在真实 VS Code 宿主里激活过。这一点写在这里而不是藏起来。
