# 咕咕嘎嘎语 · VS Code 扩展

> 给 `.咕咕` / `.ググ` / `.gu` / `.gugugaga` 文件的编辑器支持：语法着色、上下文补全、悬停释义与真实语法诊断。中文 咕嘎、日语 グガ、英语 GU/GA 三种方言可以混在同一个文件里写。

## 这是什么 / 不是什么

**是**

- 打开 `.咕咕` / `.ググ` / `.gu` / `.gugugaga` 文件即识别为咕咕嘎嘎语（语言 id `gugugaga`，后缀大小写不敏感），括号/缩进/折叠按缩进工作。清单里另登记了一条 `.ググ` 的分解写法（macOS 文件名可能是 ク + ゛ 两个码位），认不出的文档在打开时按 NFC 归一后再判一次。
- TextMate 语法着色 `source.gugugaga`：30 个保留记号、整数字面量/位串字面量、名字与标点。
- 按上下文（顶层 / 类体 / 语句 / 表达式 / 调用）给出保留词、骨架片段与本文档内已定义的名字。
- 鼠标停在记号上显示记号的释义与家族；文案同样只用 咕/嘎/！/？/：/空格/换行。
- 把 `咕咕嘎嘎 嘎嘎` 的**真实**诊断搬进编辑器：解码 stderr 上的诊断帧（位名跟随后缀：`咕`/`嘎`、`グ`/`ガ`、`GU`/`GA`，解码器三套都吃），变成 Problems 面板条目与波浪线。

**不是**

- 不是解释器，也不带运行时；跑程序仍然用 CLI。
- 不实现 LSP：没有跨文件语义、跳转定义、重命名、引用查找、格式化。

## 安装

`.vsix` 由项目维护者（lead）统一打包，安装：

```bash
code --install-extension vscode/gugugaga-language.vsix      # 在仓库根执行
```

安装后**打开 `.咕咕` / `.ググ` / `.gu` / `.gugugaga` 文件即可**（状态栏语言模式显示「咕咕嘎嘎语」）。

## 三块功能

### 1. 语言基础

四个后缀 `.咕咕` `.ググ` `.gu` `.gugugaga`（大小写不敏感）、注释关闭（本语言没有注释）、`：` 或 `:` 结尾自动缩进、`嘎嘎`/`嘎嘎嘎嘎`/`嘎嘎嘎嘎嘎嘎` 回退缩进（日语 `ガガ`、英语 `GAGA` 同样生效）、按缩进折叠、单词规则同时认 咕/グ/ぐ/GU 与 嘎/ガ/が/GA、语法着色。

三种方言对照（同一份文件、同一个词里都能混着写，内部一律归一化成 咕/嘎）：

| 位 | 中文 | 日语 | 英语 |
| --- | --- | --- | --- |
| 0 | 咕 | グ / ぐ | GU / gu |
| 1 | 嘎 | ガ / が | GA / ga |
| 标点 | ！ ？ ： | ！ ？ ： | ! ? : |

`グ咕GU！` 是一个合法的声明头；补全候选与悬停释义仍输出规范中文，诊断正文也是中文人话。

### 2. 编辑辅助

- 补全：在顶层给类头/入口头，在类体给字段与方法，在语句位给语句起始词，在 `咕：`/`嘎嘎：` 等引导符之后只给表达式起始词与名字，在 `！？` 之后只给本文档里的方法名。
- 片段：类、方法、入口、字段、条件块、循环、打印等骨架。
- 悬停：记号本身、家族、中文含义与用法示例。

### 3. 语法诊断

打开、保存、编辑（默认防抖 350ms）以及手动执行命令时，扩展会在后台跑一次 `咕咕嘎嘎 嘎嘎 <文件>`。stderr 上没有字，只有**诊断帧**（GGDIAG v1，格式见 `SPEC.md` §12；位名字形跟文件后缀：`咕`/`嘎`、`グ`/`ガ`、`GU`/`GA`）；`src/diagnostics.js` 自带零依赖解码器，把帧解成 `{行, 列, 码, 说明}` 再交给 VS Code。诊断本身不执行程序，所以只会出现 `E1xx / E2xx / E3xx`。

## 诊断需要 CLI 可达

扩展自己不实现解析器，诊断完全来自真实的解释器。找命令的顺序是三级回退：

| 优先级 | 条件 | 实际执行 |
| --- | --- | --- |
| 1 | 设置 `gugugaga.cliPath` 的值不是已知命令名（`咕咕嘎嘎`/`ググガガ`/`gggg`/`gg`），且该路径存在 | 直接执行它；若以 `.ts` 结尾，改成 `<nodePath> <该路径> 嘎嘎 <文件>` |
| 2 | 工作区根存在 `bin/gg.ts` | `<nodePath> <工作区>/bin/gg.ts 嘎嘎 <文件>` |
| 3 | 以上都不成立 | PATH 上按 `咕咕嘎嘎` → `ググガガ` → `gggg` → `gg` 取第一个存在的 |

补充：

- `cliPath` 写相对路径时，按**当前工作区根**解析；没有打开文件夹时按进程工作目录。
- 只有 code 1–21（即 `E1xx`~`E4xx`，注意没有 `E4009`）会变成诊断；code 22 是帮助帧，不算问题；code 0/23/24（用法错误/读文件失败/内部错误）变成一次静默的失败，不画波浪线。
- CLI 起不来或超时**不会弹窗**打断你，输出面板也不会写（面板只允许咕/嘎）：完整原因（exec、args、工作区、栈）走 `console.error`，在「帮助 → 切换开发人员工具」的控制台里看。

stderr 上是位流，不是文本。一帧的形状（`SPEC.md` §12）：

```text
magic 4（1010）| version 2（00）| code 8 | line 16 | col 16 | mlen 16 | msg(mlen×8) | end 3（110）
```

面板里落下的**不是中文**：条目正文是这一帧的原始位串（纯 咕/嘎），码名列留空。把它交给姊妹项目的翻译器才有人话：

```sh
ggt decode --diag <<< "嘎咕嘎咕咕咕…"     # → 2:7 E1001 非法字符“噶”（U+5676）
```

码名、位置与中文正文会同时打进开发者控制台。扩展自己不生成、也不翻译任何说明文字。

## 设置（5 个）

| 设置 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `gugugaga.cliPath` | string | `咕咕嘎嘎` | 解释器入口；填路径可指定某个 `gg.ts` 或可执行文件 |
| `gugugaga.nodePath` | string | `node` | 跑 `.ts` 形式解释器时用的 Node（可执行文件名只能是 ASCII） |
| `gugugaga.checkOnChange` | boolean | `true` | 编辑时自动检查（防抖后执行） |
| `gugugaga.debounceMs` | number | `350` | 编辑停止多久后触发检查（毫秒） |
| `gugugaga.maxSteps` | integer 或 null | `null` | 预留的执行步数上限；`check` 不执行程序，当前版本用不到 |

## 命令（3 个）

| 命令 | 作用 |
| --- | --- |
| `咕咕嘎嘎语：咕咕嘎嘎` | 运行当前文件：先存盘，再把 `咕咕嘎嘎 <文件>` 发进集成终端。出现在两处——编辑器标题栏按钮（▶，codicon `$(play)`，颜色随深浅主题）、编辑器右键菜单；只在四个后缀的文件上出现 |
| `咕咕嘎嘎语：检查当前文件` | 立刻对当前文档跑一次检查，不等防抖 |
| `咕咕嘎嘎语：显示输出面板` | 打开输出面板（面板内容只有咕/嘎 词组，不打印路径与命令行） |

运行**不捕获输出**：真正的程序位流留在终端里，因此可以继续喂 stdin、接 `| ggt decode --bytes`、看退出码。终端复用：已经有一个名为 `咕咕嘎嘎` 且没退出的终端就接着用，否则新开一个，工作目录取工作区根（没有工作区则取文件所在目录）。命令行里的 ASCII（`node`、`bin/gg.ts`、绝对路径）只进开发者控制台，面板只留一行纯咕嘎标记。不绑快捷键：命令面板里出现 ASCII 和弦会破坏纯净度。

## 纯净度闸

输出面板是对外可见面，只允许三种方言的位名（`咕`/`嘎`、`グ`/`ガ`、成对的 `GU`/`GA`）与 `！？：!?:`、空格与 U+3000。闸放宽不等于内容会变：扩展自己写进面板的行仍然全是中文位名。`append()` 写入前会过 `isPureLine()`：不纯的行不写面板、也不抛异常，完整内容退到 `console.error`（开发者控制台）。所以「为什么没有诊断」这类排查必须开「帮助 → 切换开发人员工具」。

## 已知限制

- 不实现 LSP：补全与悬停基于上下文扫描和正则，跨文件能力一概没有。
- 诊断依赖 `node` 与 `咕咕嘎嘎`（或工作区 `bin/gg.ts`）可达；环境没装好时静默无诊断，原因只在开发者控制台里。
- 跑程序请用终端：`咕咕嘎嘎 程序.咕咕`（`.ググ` / `.gu` / `.gugugaga` 同理）。本扩展只做 `嘎嘎`（检查），不执行程序、不显示位流输出。
- `gugugaga.maxSteps` 目前不生效（见上表）。
- 未保存的新建缓冲区（untitled）没有文件路径，不参与检查；先保存成 `.咕咕` 文件。
- 着色、括号/折叠配置与片段来自 `syntaxes/`、`language-configuration.json`、`snippets/`；这些文件缺失时 VS Code 会跳过对应部分，扩展本身不会崩。

## 开发与测试

```bash
cd vscode/gugugaga
node --check src/extension.js
node --test "tests/*.test.js"
```

测试不 `require("vscode")`（它只在宿主里存在），离线、零依赖、只用 `node --test`。
