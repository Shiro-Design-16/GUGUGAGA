# ググガガ語 · VS Code 拡張機能

> `.咕咕` / `.ググ` / `.gu` / `.gugugaga` ファイル向けのエディタサポート：シンタックスハイライト、コンテキスト補完、ホバーでの意味表示、そして本物の構文診断。中国語の 咕嘎、日本語の グガ、英語の GU/GA という三つの方言は、同じファイルの中に混ぜて書けます。

## これは何か / 何ではないか

**やること**

- `.咕咕` / `.ググ` / `.gu` / `.gugugaga` ファイルを開いた時点でググガガ語（中国語表記: 咕咕嘎嘎語）として認識されます（言語 id `gugugaga`、拡張子は大文字小文字を区別しません）。括弧・インデント・折りたたみはインデントに従って動作します。マニフェストには `.ググ` の分解表記（macOS ではファイル名が ク + ゛ の二つの符号位置になることがあります）も登録してあり、判定できなかった文書は開くときに NFC 正規化してからもう一度判定します。
- TextMate のシンタックスハイライト `source.gugugaga`：30 個の予約トークン、整数リテラル／ビット列リテラル、名前と記号。
- コンテキスト（トップレベル / クラス本体 / 文 / 式 / 呼び出し）に応じて、予約語、骨組みのスニペット、この文書内で定義済みの名前を提示します。
- 記号の上にマウスを置くと、その記号の意味とファミリーを表示します。表示文言も 咕/嘎/！/？/：/空白/改行 だけで書かれています。
- `咕咕嘎嘎 嘎嘎` の**本物の**診断をエディタに持ち込みます：stderr 上の 咕/嘎 の診断フレームをデコードし、Problems パネルの項目と波線に変えます。

**やらないこと**

- インタプリタではありませんし、ランタイムも積んでいません。プログラムを走らせるのは今まで通り CLI です。
- LSP は実装していません：ファイルをまたぐ意味解析、定義へのジャンプ、名前変更、参照検索、フォーマットはありません。

## インストール

`.vsix` はプロジェクトのメンテナ（lead）がまとめてパッケージします。インストールは：

```bash
code --install-extension vscode/gugugaga-language.vsix      # 在仓库根执行
```

インストール後は**`.咕咕` / `.ググ` / `.gu` / `.gugugaga` ファイルを開くだけ**です（ステータスバーの言語モードに「咕咕嘎嘎语」と表示されます）。

## 三つの機能

### 1. 言語の基礎

四つの拡張子 `.咕咕` `.ググ` `.gu` `.gugugaga`（大文字小文字を区別しません）、コメントは無効（この言語にコメントはありません）、`：` または `:` で終わると自動インデント、`嘎嘎`/`嘎嘎嘎嘎`/`嘎嘎嘎嘎嘎嘎` でインデントを戻す（日本語の `ガガ`、英語の `GAGA` でも同じように効きます）、インデントによる折りたたみ、単語規則は 咕/グ/ぐ/GU と 嘎/ガ/が/GA の両方を認識、シンタックスハイライト。

三つの方言の対応（同じファイルの中でも、同じ単語の中でも混ぜて書けます。内部では一律 咕/嘎 に正規化されます）：

| ビット | 中国語 | 日本語 | 英語 |
| --- | --- | --- | --- |
| 0 | 咕 | グ / ぐ | GU / gu |
| 1 | 嘎 | ガ / が | GA / ga |
| 句読点 | ！ ？ ： | ！ ？ ： | ! ? : |

`グ咕GU！` は合法な宣言ヘッダです。補完候補とホバーの解説は今まで通り規範的な中国語で出力され、診断の本文も中国語の人間の言葉です。

### 2. 編集支援

- 補完：トップレベルではクラスヘッダ／エントリヘッダ、クラス本体ではフィールドとメソッド、文の位置では文の開始語、`咕：`/`嘎嘎：` などの導入記号の後では式の開始語と名前だけ、`！？` の後ではこの文書内のメソッド名だけを提示します。
- スニペット：クラス、メソッド、エントリ、フィールド、条件ブロック、ループ、プリントなどの骨組み。
- ホバー：記号そのもの、ファミリー、中国語での意味、使い方の例。

### 3. 構文診断

ファイルを開く、保存する、編集する（既定のデバウンスは 350ms）、そして手動でコマンドを実行する——これらのタイミングで、拡張機能はバックグラウンドで `咕咕嘎嘎 嘎嘎 <文件>` を一度走らせます。stderr には文字がなく、**咕/嘎 の診断フレーム**だけがあります（GGDIAG v1、形式は `SPEC.md` §12 を参照）。`src/diagnostics.js` が依存ゼロのデコーダを内蔵しており、フレームを `{行, 列, 码, 说明}` に解いてから VS Code に渡します。診断自体はプログラムを実行しないので、現れるのは `E1xx / E2xx / E3xx` だけです。

## 診断には CLI への到達性が要る

拡張機能自身は構文解析器を実装しておらず、診断は完全に本物のインタプリタから来ます。コマンドを探す順序は三段階のフォールバックです：

| 優先度 | 条件 | 実際の実行 |
| --- | --- | --- |
| 1 | 設定 `gugugaga.cliPath` の値が既知のコマンド名（`咕咕嘎嘎`/`ググガガ`/`gggg`/`gg`）ではなく、かつそのパスが存在する | それをそのまま実行する。`.ts` で終わる場合は `<nodePath> <该路径> 嘎嘎 <文件>` に変える |
| 2 | ワークスペースのルートに `bin/gg.ts` がある | `<nodePath> <工作区>/bin/gg.ts 嘎嘎 <文件>` |
| 3 | 上のどれも成立しない | PATH 上で `咕咕嘎嘎` → `ググガガ` → `gggg` → `gg` の順に、最初に見つかったものを使う |

補足：

- `cliPath` に相対パスを書いた場合は、**現在のワークスペースのルート**を基準に解決します。フォルダを開いていない場合はプロセスの作業ディレクトリが基準です。
- code 1–21（つまり `E1xx`~`E4xx`、`E4009` が存在しない点に注意）だけが診断になります。code 22 はヘルプフレームで、問題には数えません。code 0/23/24（用法エラー／ファイル読み込み失敗／内部エラー）は静かな失敗になり、波線は描かれません。
- CLI が起動しない、あるいはタイムアウトした場合も**ポップアップで邪魔をすることはなく**、出力パネルにも書きません（パネルは 咕/嘎 しか許されません）。完全な理由（exec、args、ワークスペース、スタック）は `console.error` に流れ、「ヘルプ → 開発者ツールの切り替え」のコンソールで見られます。

stderr 上はテキストではなくビットストリームです。一つのフレームの形（`SPEC.md` §12）：

```text
magic 4（1010）| version 2（00）| code 8 | line 16 | col 16 | mlen 16 | msg(mlen×8) | end 3（110）
```

パネルに残るのは**中国語ではありません**：項目の本文はそのフレームの生のビット列（純粋な 咕/嘎）で、コード名の列は空のままです。姉妹プロジェクトのトランスレータに渡してはじめて人間の言葉になります：

```sh
ggt decode --diag <<< "嘎咕嘎咕咕咕…"     # → 2:7 E1001 非法字符“噶”（U+5676）
```

コード名、位置、中国語の本文は同時に開発者コンソールに出力されます。拡張機能自身は説明文を生成も翻訳もしません。

## 設定（5 個）

| 設定 | 型 | 既定値 | 説明 |
| --- | --- | --- | --- |
| `gugugaga.cliPath` | string | `咕咕嘎嘎` | インタプリタのエントリ。パスを書けば特定の `gg.ts` や実行ファイルを指定できます |
| `gugugaga.nodePath` | string | `node` | `.ts` 形式のインタプリタを動かすときの Node（実行ファイル名は ASCII のみ） |
| `gugugaga.checkOnChange` | boolean | `true` | 編集時に自動チェック（デバウンス後に実行） |
| `gugugaga.debounceMs` | number | `350` | 編集が止まってからどれだけ後にチェックするか（ミリ秒） |
| `gugugaga.maxSteps` | integer または null | `null` | 将来のための実行ステップ上限。`check` はプログラムを実行しないので、現行バージョンでは使いません |

## コマンド（3 個）

| コマンド | 動作 |
| --- | --- |
| `咕咕嘎嘎语：咕咕嘎嘎` | 現在のファイルを実行：まず保存し、次に `咕咕嘎嘎 <文件>` を統合ターミナルへ送ります。出る場所は二つ——エディタのタイトルバーのボタン（▶、codicon `$(play)`、配色は明暗テーマに追随）、エディタの右クリックメニュー。四つの拡張子のファイルでだけ現れます |
| `咕咕嘎嘎语：检查当前文件` | 現在のドキュメントをすぐ一度チェックする。デバウンスは待たない |
| `咕咕嘎嘎语：显示输出面板` | 出力パネルを開く（パネルの中身は 咕/嘎 の語句だけで、パスやコマンドラインは出力しない） |

実行は**出力をキャプチャしません**：本物のプログラムのビットストリームはターミナルに残るので、そのまま stdin に餌をやり、`| ggt decode --bytes` に繋ぎ、終了コードを見られます。ターミナルは再利用します：`咕咕嘎嘎` という名前でまだ終了していないターミナルがあればそれを使い、なければ新しく開きます（作業ディレクトリはワークスペースのルート、ワークスペースがなければファイルのあるディレクトリ）。コマンドライン中の ASCII（`node`、`bin/gg.ts`、絶対パス）は開発者コンソールにだけ流れ、パネルには純粋な咕嘎の印が一行残るだけです。ショートカットは割り当てません：コマンドパレットに ASCII の和音が現れると純度が壊れるからです。

## 純度ゲート

出力パネルは外から見える面であり、咕/嘎/！/？/：/空白 しか許されません。`append()` は書き込む前に `isPureLine()` を通します：純粋でない行はパネルに書かず、例外も投げず、完全な内容は `console.error`（開発者コンソール）へ退避します。ですから「なぜ診断が出ないのか」といった切り分けには「ヘルプ → 開発者ツールの切り替え」を開く必要があります。

## 既知の制限

- LSP は実装していません：補完とホバーはコンテキストの走査と正規表現に基づくもので、ファイルをまたぐ能力は一切ありません。
- 診断は `node` と `咕咕嘎嘎`（またはワークスペースの `bin/gg.ts`）に到達できることが前提です。環境が整っていないと静かに診断が出なくなり、理由は開発者コンソールにだけ残ります。
- プログラムの実行はターミナルで：`咕咕嘎嘎 程序.咕咕`（`.ググ` / `.gu` / `.gugugaga` も同様）。本拡張機能は `嘎嘎`（チェック）だけを行い、プログラムの実行もビットストリーム出力の表示もしません。
- `gugugaga.maxSteps` は現在効きません（上の表を参照）。
- 未保存の新規バッファ（untitled）にはファイルパスがないため、チェックの対象になりません。まず `.咕咕` ファイルとして保存してください。
- ハイライト、括弧・折りたたみの設定、スニペットは `syntaxes/`、`language-configuration.json`、`snippets/` から来ています。これらのファイルが欠けていると VS Code は該当部分を飛ばしますが、拡張機能自体は落ちません。

## 開発とテスト

```bash
cd vscode/gugugaga
node --check src/extension.js
node --test "tests/*.test.js"
```

テストは `require("vscode")` を呼びません（それはホストの中にしか存在しないため）。オフライン、依存ゼロ、`node --test` だけを使います。
