# 翻译规范（i18n）

本文件是多语言文档的**唯一权威规则**。任何译文与它冲突，以本文件为准；本文件与中文原文事实冲突，以中文原文为准。

## 0. 范围与产物

9 份中文文档 × 2 种语言 = 18 个新文件。文件名 = 原文件名去掉 `.md`，加 `.ja.md` / `.en.md`，**同目录并排**：

| 中文原文 | 日语 | 英语 |
| --- | --- | --- |
| `README.md` | `README.ja.md` | `README.en.md` |
| `TUTORIAL.md` | `TUTORIAL.ja.md` | `TUTORIAL.en.md` |
| `SPEC.md` | `SPEC.ja.md` | `SPEC.en.md` |
| `translator/README.md` | `translator/README.ja.md` | `translator/README.en.md` |

## 1. 文件头（每个译文文件必须有，逐字照抄下面模板）

日语文件开头：

```text
<!-- i18n:begin -->
[中文](ORIGINAL) ｜ **日本語** ｜ [English](TARGET_EN)

> 本ファイルは日本語訳です。内容の正本は中国語版 [ORIGINAL](ORIGINAL) で、差分があれば中国語版が優先します。
<!-- i18n:end -->
```

英语文件开头：

```text
<!-- i18n:begin -->
[中文](ORIGINAL) | **English** | [日本語](TARGET_JA)

> This is an English translation. The Chinese [ORIGINAL](ORIGINAL) is authoritative; if they diverge, the Chinese version wins.
<!-- i18n:end -->
```

`ORIGINAL` / `TARGET_JA` / `TARGET_EN` 换成同目录文件名（例如写 `README.ja.md` 时：`ORIGINAL=README.md`、`TARGET_EN=README.en.md`）。标记行 `<!-- i18n:begin -->` 与 `<!-- i18n:end -->` 必须原样保留——校验脚本靠它们跳过头部。

## 2. 必须原样照抄（永不翻译、不改写）

1. **程序输出**：`E1001 非法字符“噶”（U+5676）`、`嗨`、`E5 97 A8`、目录树、`GGDIAG` 帧解码结果——这些是工具真实打印的东西，改了就是文档说谎。
2. **命令、路径、文件名**：`咕咕嘎嘎`、`ググガガ`、`gggg`、`ggt`、`node bin/ggt.ts`、`examples/咕嘎咕嘎.咕咕`、`src/lexer.ts`、`translator/bin/ggt.ts`。
3. **数字与统计**：`134`、`100`、`167`、`401`、`5000000`、`512`、`65535`、`21`、`30`、`0`–`24` 号事件、`U+5495`、`U+3000`。译文里数字个数必须与原文一致（用阿拉伯数字，不要写「三百九十四」）。
4. **语言自身的拼写**：保留词（`咕咕！`、`嘎嘎`、`咕咕嘎嘎！` 等）、错误码（`E1001`）、`GGDIAG v1`、版本号 `1.0.0`。正文里提到它们时用行内代码包住。
5. **代码块的围栏语言标记与顺序**（` ```text ` / ` ```bash ` / ` ```sh ` / ` ```js `）以及代码块个数——校验脚本逐块比对。
6. **标题编号**：`## 3. 语言速览` → `## 3. 言語概観`（编号与层级不变）。
7. **表格的行列结构**：行数、列数、对齐行不变。

## 3. 代码块里的「咕嘎语源码」按方言改写

只是**源码示例**才改写；输出、命令、图表不动（见 §2）。

- 日语版：`咕`→`グ`、`嘎`→`ガ`，`！？：` 保持全角，缩进与间隔空格改成全角空格 `U+3000`。
- 英语版：`咕`→`GU`、`嘎`→`GA`，标点改成半角 `!` `?` `:`，空格用半角空格。逐个字符替换，**缩进的格数不变**（原文 4 个空格 → 日语 4 个 `U+3000` → 英语 4 个空格）。
- 大小写：英语版任意大小写都合法，但**统一写全大写** `GU`/`GA`，不要在同一个文件里混。
- **例外（不改写）**：演示非法字符或故意报错的片段（含 `噶` 之类非位名字符）原样保留——否则报错正文里的字符就对不上了。这类片段的输出照样逐字照抄。
- 不许把源码块「顺手美化」（增减空行、改变量名、换行位置）。除了方言替换，字符级必须与原文一致。

## 5. 语气

这是整活项目，文档有幽默与自嘲（「究极简陋版」「名字经济学」「不会用在真实工程」）。译文要把这层语气带过去，别写成企业规格书。日语用「です・ます」体，技术判断句可以「〜です／〜します」；英语用短句、直白、可以 dry humor，不要营销腔。

## 6. 结构必须一一对应

不增章节、不删章节、不合并章节、不调换顺序。译注只能在原处用一行 `> 訳注：…` / `> Translator's note: …`，全篇总数不超过 3 处，且不得引入原文没有的事实。

## 7. 自检（交活前必须自己跑，把输出贴进回报）

```bash
node scripts/check-translations.mjs SPEC ja          # 单份单语言（第一个参数是路径前缀，可省略 .md；第二个可选 ja / en）
node scripts/check-translations.mjs translator/README  # 路径前缀命中的文档，两种语言都查
node scripts/check-translations.mjs             # 全部 18 份
```

脚本检查：i18n 头部存在且语言标记正确、标题数量与层级序列、代码块数量与语言序列、源码块方言等价、输出块逐字一致、数字多重集一致、ASCII 行内代码集合一致、可运行示例真跑后 stdout 逐字节一致。**任何一项红都不许交活**。

## 8. 禁止

1. 把 `咕`/`嘎` 音译成 `gu`/`ga` 或写成单词。
2. 改数字、改测试条数、改版本、改路径、改错误码、改输出。
3. 新增原文没有的章节、示例、命令、结论。
4. 把中文原文的代码块「修正」成你认为更正确的写法——原文错就是错，照译并在回报里指出，由调度者裁决。
5. 翻译 `<!-- i18n:begin -->` / `<!-- i18n:end -->` 标记本身，或删掉它们。
