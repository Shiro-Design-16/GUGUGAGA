# ググガガ語（中国語表記: 咕咕嘎嘎語）· 名前対応表

> ソースの中のビットは 0 と 1 の二種類だけです。既定では `咕`/`嘎` で書き、`グ`/`ガ`（日本語、`ぐ`/`が` も可）や `GU`/`GA`（英語、大文字小文字を区別しない）でも書けます。三方言はビット位置ごとに等価で、混ぜ書きできます。この表では一貫して中国語方言を使います。
> この表は各例のビット列を人間の言葉に翻訳し、Java の概念に対応づけたものです。人間がこうしたプログラムを読むための助けになります。
> ファイル名は純粋な咕嘎に変えてあります（`examples/咕嘎咕嘎.咕咕` など）。画面や `ls` に出るものだからです。ディレクトリ名（`src/`、`tests/` など）は ASCII のままにしています：あれはホスト側ツールチェーンの骨組みで、変えると Node のモジュール解決が壊れます。

## 0. 共通早見表

### 0.1 構文糖

| 字列 | 意味 | Java の概念 |
| --- | --- | --- |
| `咕咕！ <名前>` | クラスを定義 | `class` |
| `咕咕！ <子クラス>：<親クラス>？` | 継承 | `extends` |
| `咕咕嘎！ <メソッド名> [：<引数>]*` | メソッドを定義；メソッド名がクラス名と同じならコンストラクタ | メソッド / コンストラクタ |
| `咕咕嘎嘎！ <名前>` | プログラムのエントリ（静的コンテキストで、「自分」は無い） | `public static void main(String[])` |
| `咕嘎嘎！ <クラス名>？ [：<実引数>]*` | インスタンスを生成 | `new` |
| `咕咕！？ <名前>：<式>` | クラス本体ではフィールド宣言；メソッド本体では代入 / ローカル変数の宣言 | フィールド宣言 / `x = expr` |
| `咕咕！？ <原子> <メンバ名>：<式>` | オブジェクトのフィールドに書き込む | `obj.field = expr` |
| `咕嘎！？ <式>` | 評価して結果を捨てる（副作用のため） | `expr;` |
| `咕：<式>` | 出力（生のビットストリームを書き出す） | `System.out.write(...)` |
| `嘎嘎：<式>` | 戻る | `return` |
| `嘎嘎嘎：<条件>` + インデントブロック | もし | `if` |
| `嘎嘎嘎嘎` + インデントブロック | そうでなければ（同じ階層の「もし」の直後に置く必要がある） | `else` |
| `嘎嘎嘎嘎嘎：<条件>` + インデントブロック | ループ | `while` |
| `嘎嘎嘎嘎嘎嘎` | 自分 | `this` |
| `嘎嘎嘎嘎嘎嘎嘎` | stdin から 1 バイト読む → 整数 0–255；EOF なら空 | `System.in.read()` |
| `<名前>？` | その名前を読む | 変数/フィールド/引数の評価 |
| `<レシーバ> <メソッド名>！ [：<実引数>]*` | メソッド呼び出し（実引数の個数 = `：` スロットの個数） | `recv.m(args)` |
| `嘎嘎嘎？<ビット列>` | 整数（二進表記、`咕`=0 `嘎`=1） | `int` リテラル |
| `嘎嘎嘎嘎？<ビット列>` | ビット列リテラル（ビットごとにそのまま。バイト規約では UTF-8 の断片） | `byte[]` 定数 |
| `嘎嘎？` / `嘎嘎咕？` / `嘎咕？` | 真 / 偽 / 空 | `true` / `false` / `null` |

### 0.2 演算子（前置記法。括弧は無く、入れ子の実引数は先にローカル変数へ束縛する）

| 字列 | 意味 | Java の概念 |
| --- | --- | --- |
| `咕？` | 加算（整数の足し算；ビット列二つなら連結） | `+` |
| `咕咕？` `咕嘎？` `咕咕咕？` `咕咕嘎？` | 減算 乗算 除算（ゼロ方向への切り捨て） 剰余 | `-` `*` `/` `%` |
| `咕嘎咕？` `咕嘎嘎？` `咕嘎嘎咕？` | 等しい 小さい 大きい | `==` `<` `>` |
| `咕嘎咕咕？` `咕嘎咕嘎？` `咕咕咕咕？` | 論理積 論理和 否定（両辺とも評価する。短絡しない） | `&&` `\|\|` `!` |
| `咕咕嘎咕？` | 負 | 単項 `-` |

### 0.3 出力エンコーディング（SPEC §6）

| 値の型 | 出力 | Java の概念 |
| --- | --- | --- |
| 整数 | 固定長 64 ビットの補数、上位ビットが先；範囲を超えたら下位 64 ビットを取る | `long` |
| ビット列 | そのままビットごとに写す | `byte[]` |
| ブール | 8 ビット：偽 = `咕` 8 個、真 = `嘎` 8 個 | 1 バイト |
| 空 / オブジェクト | E4006 を報告し、出力できない | — |

stdout は**連続した生のビットストリーム**です：区切り文字も、改行も、末尾の改行もありません。文字列はビット列で UTF-8（バイトあたり 8 ビット、上位ビットが先）として表します。

## 1. `examples/咕嘎咕嘎.咕咕`

用途：UTF-8 文字「嗨」の三バイトを出力し、「ビット列リテラル + 連結」を示します。

| ビット列 | 中国語での意味 | Java の概念 |
| --- | --- | --- |
| `嘎咕嘎嘎嘎咕` | エントリ名（適当に付けたもの。何でもよい） | `main` メソッド名 |
| `嘎嘎嘎嘎？嘎嘎嘎咕咕嘎咕` | ビット列 `11100101` = 0xE5（「嗨」の UTF-8 第 1 バイト） | `(byte)0xE5` |
| `嘎嘎嘎嘎？嘎咕咕嘎咕嘎嘎嘎` | ビット列 `10010111` = 0x97（第 2 バイト） | `(byte)0x97` |
| `嘎嘎嘎嘎？嘎咕嘎咕嘎咕咕咕` | ビット列 `10101000` = 0xA8（第 3 バイト） | `(byte)0xA8` |
| `咕？` | ビット列の連結（二回） | 文字列/配列の連結 |
| `咕：` | 24 ビットの生のビットストリームを出力 | `System.out.write(new byte[]{...})` |

期待される出力：`11100101 10010111 10101000`（24 ビット、途中に空白も改行も無し）= `E5 97 A8` = 「嗨」。

用途：クラス + フィールド + インクリメント/取得メソッド + 5 回のループで、64 ビット整数の出力を示します。

| ビット列 | 中国語での意味 | Java の概念 |
| --- | --- | --- |
| `嘎咕嘎咕嘎` | カウンタのクラス | `class Counter` |
| `嘎咕咕嘎咕` | カウント値（フィールド） | `int count` |
| `嘎咕嘎咕嘎` | コンストラクタ（クラス名と同じ、引数 0 個） | `Counter()` |
| `嘎咕嘎咕咕` | インクリメント | `void inc()` |
| `嘎咕咕嘎嘎` | 値の取得 | `int get()` |
| `嘎咕嘎咕嘎咕` | エントリ | `main` |
| `嘎嘎咕嘎咕` | カウンタのインスタンス | `Counter c` |
| `嘎咕咕咕嘎` | ループ変数 | `int i` |
| `嘎嘎嘎？咕` / `嘎嘎嘎？嘎` / `嘎嘎嘎？嘎咕嘎` | 整数 0 / 1 / 5 | `0` / `1` / `5` |
| `咕嘎嘎？` | 小さい | `<` |

期待される出力：`i = 1,2,3,4,5` の 64 ビット補数が順に連結されたもの（320 ビット）。

## 3. `examples/嘎嘎咕咕.咕咕`

用途：親クラス + 子クラスの継承、引数付きコンストラクタ、子クラスによる同名メソッドのオーバーライド。親/子の二つのレシーバからそれぞれ一度ずつ呼び、動的ディスパッチを示します。

| ビット列 | 中国語での意味 | Java の概念 |
| --- | --- | --- |
| `嘎嘎咕嘎嘎` | 親クラス | `class Base` |
| `嘎嘎咕嘎嘎咕` | 子クラス | `class Sub extends Base` |
| `嘎咕咕嘎咕` | タグのフィールド（親クラスで宣言し、子クラスが継承する） | `byte[] tag` |
| `嘎咕咕咕嘎` | コンストラクタの引数 | `byte[] tag` |
| `嘎嘎咕嘎嘎：嘎咕咕咕嘎` | 親クラスのコンストラクタ（引数 1 個） | `Base(byte[] tag)` |
| `嘎嘎咕嘎嘎咕：嘎咕咕咕嘎` | 子クラスのコンストラクタ（引数 1 個） | `Sub(byte[] tag)` |
| `嘎咕嘎嘎咕` | メソッド。子クラスで同名にオーバーライドされる | `byte[] speak()` |
| `嘎咕嘎嘎嘎咕` | エントリ | `main` |
| `嘎嘎咕嘎咕咕` / `嘎嘎咕嘎咕嘎` | 親クラスのインスタンス / 子クラスのインスタンス | `Base p` / `Sub c` |
| `嘎嘎嘎嘎嘎嘎` | 自分（自分のフィールドを読む） | `this` |
| `嘎嘎嘎嘎？嘎嘎嘎嘎咕咕咕咕` | 0xF0 | `(byte)0xF0` |
| `嘎嘎嘎嘎？嘎嘎嘎嘎嘎嘎嘎嘎` | 0xFF | `(byte)0xFF` |
| `咕？` | 二つのビット列の連結 | 配列の連結 |

期待される出力：親クラスのレシーバ → 8 ビット `11110000`（0xF0）；子クラスのレシーバ → 16 ビット `11111111 11111111`（0xFF 0xFF）。同じメソッド名で二つの異なる結果、これが動的ディスパッチです。

## 4. `examples/咕嘎嘎咕.咕咕`

用途：stdin から二バイト読み、加算と減算を行って、二つの 64 ビット整数を出力します。

| ビット列 | 中国語での意味 | Java の概念 |
| --- | --- | --- |
| `嘎咕嘎嘎嘎咕` | エントリ | `main` |
| `嘎嘎咕嘎咕咕` / `嘎嘎咕嘎咕嘎` | 読み取った二バイト | `int a, b` |
| `嘎嘎嘎嘎嘎嘎嘎` | 1 バイト読み込む → 0–255 | `System.in.read()` |
| `咕？` / `咕咕？` | 加算 / 減算 | `a + b` / `a - b` |

**stdin に何を流すか**：プログラムは続けて 2 バイト読むので、少なくとも 2 バイトは流す必要があります。例えば：

```sh
printf '35' | node bin/gg.ts examples/咕嘎嘎咕.咕咕   # 读 0x33=51、0x35=53
printf '\003\005' | node bin/gg.ts examples/咕嘎嘎咕.咕咕   # 读 3、5
```

- `printf '35'`：加算 = 51+53 = **104**、減算 = 51−53 = **−2**、出力は 64+64 = 128 ビット（前の 64 ビットが 104、後の 64 ビットが −2 の補数）。
- `printf '\003\005'`：加算 = **8**、減算 = **−2**。
- 1 バイトだけ流す（または空の stdin）：二回目の読み取りは「空」になり、その後の `加/减` が非整数に当たって → 実行期エラー E4004。

## 5. `examples/嘎咕嘎咕.咕咕`

用途：ブール演算（小さい、論理積、否定）と「もし / そうでなければ」の二つの経路が、それぞれ見分けのつくビット列を一つずつ出力します。

| ビット列 | 中国語での意味 | Java の概念 |
| --- | --- | --- |
| `嘎咕嘎嘎嘎咕` | エントリ | `main` |
| `嘎嘎咕嘎咕咕` / `嘎嘎咕嘎咕嘎` | 二つの整数（5 と 7） | `int a = 5, b = 7` |
| `嘎嘎嘎？嘎嘎咕` / `嘎嘎嘎？嘎嘎嘎` | 整数 5 / 7 | `5` / `7` |
| `咕嘎嘎？` | 小さい | `a < b` |
| `咕嘎咕咕？` | 論理積 | `&&` |
| `咕咕咕咕？` | 否定 | `!` |
| `嘎嘎嘎：` | もし | `if` |
| `嘎嘎嘎嘎` | そうでなければ | `else` |
| `嘎嘎嘎嘎？嘎咕嘎咕嘎咕嘎咕` | 0xAA（「真」の分岐のラベル） | `(byte)0xAA` |
| `嘎嘎嘎嘎？嘎嘎嘎嘎嘎嘎嘎嘎` | 0xFF（「偽」の分岐のラベル） | `(byte)0xFF` |

期待される出力：一つ目の「もし」（`a < b` が真）は**真**の分岐へ → `10101010`（0xAA）；二つ目の「もし」（`非 (a < b)` が偽）は**そうでなければ**の分岐へ → `11111111`（0xFF）。合計 16 ビットで、両方の経路が実行されます。

## 5.5 二つの方言サンプル（`examples/ガググガグ.ググ` / `examples/gugugaga.gu`）

この二つのサンプルは `SPEC.md` §11 のあの最小プログラム（クラス + フィールド + メソッド + 生成 + 呼び出し）を方言で書いたもので、ビットストリームはバイト単位で同一、どちらも 64 ビット整数 0（フィールドは `嘎嘎嘎？咕` に初期化）で、デコードすると `0` になります。次の表は同じコードを三つの方言で綴ったものです：

| 概念 | 中国語 | 日本語 | 英語 |
| --- | --- | --- | --- |
| エントリの頭 | `咕咕嘎嘎！` | `ググガガ！` | `GUGUGAGA!` |
| 出力 | `咕：` | `グ：` | `GU:` |
| 整数リテラルの前置き | `嘎嘎嘎？` | `ガガガ？` | `GAGAGA?` |
| ビット 1 | `嘎` | `ガ` | `GA` |
| インデント | 半角スペース 4 個 | 全角スペース 4 個 U+3000 | 半角スペース 4 個 |

違いは綴りとインデントの文字だけで、構文構造・記号の種類・意味はまったく同じです：名前は混ぜて並べられます（`ガグGA` は合法な名前）。英語のビット名は必ず対にします（単独の `g` は E1001）。ファイルの拡張子も「プログラムかどうか」の判定材料にすぎません：`.咕咕` / `.ググ` / `.gu` / `.gugugaga` のどれも認識されます。

## 6. 動かしてみる

```sh
node bin/gg.ts examples/咕嘎咕嘎.咕咕              # 退出码 0；stdout 是 24 位裸位流
node bin/gg.ts examples/咕咕嘎嘎.咕咕 | wc -m         # 320 个字符（咕/嘎），没有换行；`wc -c` 会得 960，因为每个字占 3 字节
node --test "tests/**/*.test.ts"                     # 示例端到端 + 字符集校验
```

注意：stdout には**改行がありません**。`cat` をそのまま使わないでください（プロンプトが次の行に押し出されて、止まったように見えます）。結果を見たいときはリダイレクトするか、`| wc -m` で文字数を数えるか、`| head -c 60` でバイトを切り出してください。
