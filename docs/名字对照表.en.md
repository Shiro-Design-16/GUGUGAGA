# The Gugugaga language · name reference

> A bit in the source code has only two values: 0 and 1; by default it is written `咕`/`嘎`, but `グ`/`ガ` (Japanese, also `ぐ`/`が`) or `GU`/`GA` (English, case-insensitive) are accepted too. The three dialects are equivalent position by position and may be mixed; this table always uses the Chinese dialect.
> This table translates the bit strings in each example into plain language and maps them onto Java concepts, so that humans can read these programs.
> File names were changed to pure guga (`examples/咕嘎咕嘎.咕咕` and so on) because file names show up on screen and in `ls`. Directory names (`src/`, `tests/` and so on) stay ASCII: they are the skeleton of the host toolchain, and changing them would break Node's module resolution.

## 0. General quick reference

### 0.1 Syntactic sugar

| Bit string | Meaning | Java concept |
| --- | --- | --- |
| `咕咕！ <名字>` | defines a class | `class` |
| `咕咕！ <子类>：<父类>？` | inheritance | `extends` |
| `咕咕嘎！ <方法名> [：<参数>]*` | defines a method; when the method name equals the class name it is a constructor | method / constructor |
| `咕咕嘎嘎！ <名字>` | program entry (static context, no “self”) | `public static void main(String[])` |
| `咕嘎嘎！ <类名>？ [：<实参>]*` | creates an instance | `new` |
| `咕咕！？ <名字>：<表达式>` | in a class body = field declaration; in a method body = assignment / new local | field declaration / `x = expr` |
| `咕咕！？ <原子> <成员名>：<表达式>` | writes an object field | `obj.field = expr` |
| `咕嘎！？ <表达式>` | evaluates and discards the result (used for side effects) | `expr;` |
| `咕：<表达式>` | prints (writes the bare bit stream) | `System.out.write(...)` |
| `嘎嘎：<表达式>` | returns | `return` |
| `嘎嘎嘎：<条件>` + indented block | if | `if` |
| `嘎嘎嘎嘎` + indented block | else (must directly follow an “if” at the same level) | `else` |
| `嘎嘎嘎嘎嘎：<条件>` + indented block | loop | `while` |
| `嘎嘎嘎嘎嘎嘎` | self | `this` |
| `嘎嘎嘎嘎嘎嘎嘎` | reads 1 byte from stdin → integer 0–255; EOF → null | `System.in.read()` |
| `<名字>？` | reads that name | variable / field / parameter evaluation |
| `<接收者> <方法名>！ [：<实参>]*` | method call (argument count = number of `：` slots) | `recv.m(args)` |
| `嘎嘎嘎？<位串>` | integer (binary spelling, `咕`=0 `嘎`=1) | `int` literal |
| `嘎嘎嘎嘎？<位串>` | bit-string literal (copied bit for bit; under the byte convention it is a UTF-8 fragment) | `byte[]` constant |
| `嘎嘎？` / `嘎嘎咕？` / `嘎咕？` | true / false / null | `true` / `false` / `null` |

### 0.2 Operators (prefix form, no parentheses; nested arguments have to be bound to a local variable first)

| Bit string | Meaning | Java concept |
| --- | --- | --- |
| `咕？` | add (integer addition; two bit strings = concatenation) | `+` |
| `咕咕？` `咕嘎？` `咕咕咕？` `咕咕嘎？` | subtract  multiply  divide (truncated toward zero)  remainder | `-` `*` `/` `%` |
| `咕嘎咕？` `咕嘎嘎？` `咕嘎嘎咕？` | equal  less than  greater than | `==` `<` `>` |
| `咕嘎咕咕？` `咕嘎咕嘎？` `咕咕咕咕？` | and  or  not (both sides are evaluated, no short-circuit) | `&&` `\|\|` `!` |
| `咕咕嘎咕？` | negate | unary `-` |

### 0.3 Output encoding (SPEC §6)

| Value type | Output | Java concept |
| --- | --- | --- |
| integer | fixed-width 64-bit two's complement, most significant bit first; anything wider keeps the low 64 bits | `long` |
| bit string | copied bit for bit, unchanged | `byte[]` |
| boolean | 8 bits: false = 8 `咕`, true = 8 `嘎` | 1 byte |
| null / object | reports E4006, cannot be printed | — |

stdout is a **continuous bare bit stream**: no separators, no newlines, no trailing newline. Strings are always represented as bit strings in UTF-8 (8 bits per byte, most significant bit first).

## 1. `examples/咕嘎咕嘎.咕咕`

Purpose: print the three bytes of the UTF-8 character 嗨, demonstrating “bit-string literal + concatenation”.

| Bit string | Meaning | Java concept |
| --- | --- | --- |
| `嘎咕嘎嘎嘎咕` | entry name (invented; any name would do) | `main` method name |
| `嘎嘎嘎嘎？嘎嘎嘎咕咕嘎咕` | bit string `11100101` = 0xE5 (byte 1 of 嗨 in UTF-8) | `(byte)0xE5` |
| `嘎嘎嘎嘎？嘎咕咕嘎咕嘎嘎嘎` | bit string `10010111` = 0x97 (byte 2) | `(byte)0x97` |
| `嘎嘎嘎嘎？嘎咕嘎咕嘎咕咕咕` | bit string `10101000` = 0xA8 (byte 3) | `(byte)0xA8` |
| `咕？` | bit-string concatenation (twice) | string / array concatenation |
| `咕：` | prints a 24-bit bare bit stream | `System.out.write(new byte[]{...})` |

Expected output: `11100101 10010111 10101000` (24 bits, no spaces and no newlines in between) = `E5 97 A8` = 嗨.

## 2. `examples/咕咕嘎嘎.咕咕`

Purpose: class + field + increment / getter methods + a loop of 5 iterations, demonstrating 64-bit integer output.

| Bit string | Meaning | Java concept |
| --- | --- | --- |
| `嘎咕嘎咕嘎` | counter class | `class Counter` |
| `嘎咕咕嘎咕` | counter value (field) | `int count` |
| `嘎咕嘎咕嘎` | constructor (same name as the class, 0 arguments) | `Counter()` |
| `嘎咕嘎咕咕` | increment | `void inc()` |
| `嘎咕咕嘎嘎` | getter | `int get()` |
| `嘎咕嘎咕嘎咕` | entry | `main` |
| `嘎嘎咕嘎咕` | counter instance | `Counter c` |
| `嘎咕咕咕嘎` | loop variable | `int i` |
| `嘎嘎嘎？咕` / `嘎嘎嘎？嘎` / `嘎嘎嘎？嘎咕嘎` | integer 0 / 1 / 5 | `0` / `1` / `5` |
| `咕嘎嘎？` | less than | `<` |

Expected output: the 64-bit two's complements of `i = 1,2,3,4,5` laid out one after another (320 bits).

## 3. `examples/嘎嘎咕咕.咕咕`

Purpose: a base class + subclass inheritance, constructors with parameters, and a subclass overriding a method of the same name; the method is called once through the base-class receiver and once through the subclass receiver, showing dynamic dispatch.

| Bit string | Meaning | Java concept |
| --- | --- | --- |
| `嘎嘎咕嘎嘎` | base class | `class Base` |
| `嘎嘎咕嘎嘎咕` | subclass | `class Sub extends Base` |
| `嘎咕咕嘎咕` | tag field (declared by the base class, inherited by the subclass) | `byte[] tag` |
| `嘎咕咕咕嘎` | constructor parameter | `byte[] tag` |
| `嘎嘎咕嘎嘎：嘎咕咕咕嘎` | base-class constructor (1 argument) | `Base(byte[] tag)` |
| `嘎嘎咕嘎嘎咕：嘎咕咕咕嘎` | subclass constructor (1 argument) | `Sub(byte[] tag)` |
| `嘎咕嘎嘎咕` | method, overridden under the same name in the subclass | `byte[] speak()` |
| `嘎咕嘎嘎嘎咕` | entry | `main` |
| `嘎嘎咕嘎咕咕` / `嘎嘎咕嘎咕嘎` | base-class instance / subclass instance | `Base p` / `Sub c` |
| `嘎嘎嘎嘎嘎嘎` | self (reads its own field) | `this` |
| `嘎嘎嘎嘎？嘎嘎嘎嘎咕咕咕咕` | 0xF0 | `(byte)0xF0` |
| `嘎嘎嘎嘎？嘎嘎嘎嘎嘎嘎嘎嘎` | 0xFF | `(byte)0xFF` |
| `咕？` | concatenation of two bit strings | array concatenation |

Expected output: the base-class receiver → 8 bits `11110000` (0xF0); the subclass receiver → 16 bits `11111111 11111111` (0xFF 0xFF). Same method name, two different results — that is dynamic dispatch.

## 4. `examples/咕嘎嘎咕.咕咕`

Purpose: read two bytes from stdin, add them and subtract them, and print two 64-bit integers.

| Bit string | Meaning | Java concept |
| --- | --- | --- |
| `嘎咕嘎嘎嘎咕` | entry | `main` |
| `嘎嘎咕嘎咕咕` / `嘎嘎咕嘎咕嘎` | the two bytes that were read | `int a, b` |
| `嘎嘎嘎嘎嘎嘎嘎` | reads 1 byte → 0–255 | `System.in.read()` |
| `咕？` / `咕咕？` | add / subtract | `a + b` / `a - b` |

**What to feed stdin**: the program reads 2 bytes in a row, so you have to feed it at least 2 bytes. For example:

```sh
printf '35' | node bin/gg.ts examples/咕嘎嘎咕.咕咕   # 读 0x33=51、0x35=53
printf '\003\005' | node bin/gg.ts examples/咕嘎嘎咕.咕咕   # 读 3、5
```

- `printf '35'`: add = 51+53 = **104**, subtract = 51−53 = **−2**, so it prints 64+64 = 128 bits (the first 64 bits are 104, the last 64 bits are the two's complement of −2).
- `printf '\003\005'`: add = **8**, subtract = **−2**.
- Feeding only 1 byte (or an empty stdin): the second read yields null, and then `加/减` meets a non-integer → runtime error E4004.

## 5. `examples/嘎咕嘎咕.咕咕`

Purpose: boolean operations (less than, and, not) and two paths, “if / else”, each printing a bit string you can tell apart.

| Bit string | Meaning | Java concept |
| --- | --- | --- |
| `嘎咕嘎嘎嘎咕` | entry | `main` |
| `嘎嘎咕嘎咕咕` / `嘎嘎咕嘎咕嘎` | two integers (5 and 7) | `int a = 5, b = 7` |
| `嘎嘎嘎？嘎嘎咕` / `嘎嘎嘎？嘎嘎嘎` | integers 5 / 7 | `5` / `7` |
| `咕嘎嘎？` | less than | `a < b` |
| `咕嘎咕咕？` | and | `&&` |
| `咕咕咕咕？` | not | `!` |
| `嘎嘎嘎：` | if | `if` |
| `嘎嘎嘎嘎` | else | `else` |
| `嘎嘎嘎嘎？嘎咕嘎咕嘎咕嘎咕` | 0xAA (the label of the “true” branch) | `(byte)0xAA` |
| `嘎嘎嘎嘎？嘎嘎嘎嘎嘎嘎嘎嘎` | 0xFF (the label of the “false” branch) | `(byte)0xFF` |

Expected output: the first “if” (`a < b` is true) takes the **true** branch → `10101010` (0xAA); the second “if” (`非 (a < b)` is false) takes the **else** branch → `11111111` (0xFF). 16 bits in total, and both paths are exercised.

## 5.5 Two dialect examples (`examples/ガググガグ.ググ` / `examples/gugugaga.gu`)

These two examples are the dialect spellings of the minimal program in `SPEC.md` §11 (class + field + method + new + call) — once normalized the bit streams are identical bit for bit, both are the 64-bit integer 0 (the field is initialized to `嘎嘎嘎？咕`), which decodes to `0`. Output glyphs follow the file extension: the Chinese example prints 64 `咕`/`嘎` (192 bytes), the Japanese example 64 `グ`/`ガ` (192 bytes), and the English example 128 `GU`/`GA` letters (128 bytes). The table below shows the same piece of code spelled in the three dialects:

| Concept | Chinese | Japanese | English |
| --- | --- | --- | --- |
| entry header | `咕咕嘎嘎！` | `ググガガ！` | `GUGUGAGA!` |
| print | `咕：` | `グ：` | `GU:` |
| integer literal prefix | `嘎嘎嘎？` | `ガガガ？` | `GAGAGA?` |
| bit 1 | `嘎` | `ガ` | `GA` |
| indentation | 4 ASCII spaces | 4 full-width spaces, U+3000 | 4 ASCII spaces |

The difference is only spelling and the indentation character; the syntax structure, the token kinds and the semantics are exactly the same: names may mix scripts (`ガグGA` is a legal name), and English bit names have to come in pairs (a lone `g` is E1001). The file extension is only the test for “is this a program”: `.咕咕` / `.ググ` / `.gu` / `.gugugaga` are all recognized.

## 6. Running it

```sh
node bin/gg.ts examples/咕嘎咕嘎.咕咕              # 退出码 0；stdout 是 24 位裸位流
node bin/gg.ts examples/咕咕嘎嘎.咕咕 | wc -m         # 320 个字符（咕/嘎），没有换行；`wc -c` 会得 960，因为每个字占 3 字节
node --test "tests/**/*.test.ts"                     # 示例端到端 + 字符集校验
```

Note: stdout has **no trailing newline**, so do not `cat` it directly (the prompt is pushed onto the next line and it looks stuck). To see the result, redirect it, or use `| wc -m` to count characters, `| head -c 60` to take a slice of bytes.
