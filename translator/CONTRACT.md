# 咕嘎翻译器 · 契约（冻结，改动须由调度者改）

本文件是**咕嘎翻译器**项目的接口契约。翻译器是「咕咕嘎嘎语」的姊妹项目：语言那边只负责把裸位流写到 stdout，可读性由本项目负责。

## 0. 位置与解耦

- 落地目录：`translator/`（相对仓库根；仅因沙箱只能写本 workspace 才放在这里，逻辑上是独立项目：自己的 package.json / README / tests）。
- **禁止** `import` 语言实现的任何模块（`../src/**`、`../bin/**`）。唯一允许的耦合是端到端测试里**以子进程方式**执行 `../bin/gg.ts run ../examples/xxx.咕咕`。
- 零依赖：只用 Node 内置模块（`node:fs` / `node:process` / `node:path` / `node:test` / `node:assert`）。
- 源码是 `.ts`，靠 Node 类型剥离直接跑（与语言主项目一致，Node 24 实测可行）。

## 1. 输入约定（来自语言 README §4）

位流文本只含两种字符：`咕`(0) 与 `嘎`(1)。解码器**容忍空白**：空格、`\t`、`\n`、`\r` 在读入时丢弃；出现任何其它字符即错误（退出码 1），错误信息必须报出该字符与码点（形如 `非法字符“x”（U+XXXX），位于输入第 N 个字符`），其中 N 是它在输入里的**从 1 开始的字符下标**（按码点计数）。

值编码（解码端必须逐条实现）：

| 类型 | 位宽 | 编码 |
| --- | --- | --- |
| 整数 int64 | 64 | 补码，高位在前 |
| 位串 bits(n) | n | 原样，高位在前 |
| 字节 bytes(n) | 8n | 每 8 位一个字节，高位在前，整体按 UTF-8 解释 |
| 布尔 bool | 8 | 8 个 `咕` = 假，8 个 `嘎` = 真 |

## 2. CLI 契约

```text
用法：
  ggt decode [--plan <文件>] [--int64|--bytes|--hex|--bits] [<位流文件>]
  ggt encode [--int64|--as-literal] [<文本文件>]
  ggt --help

未给 <文件> 时从 stdin 读；给出时从文件读。
退出码：0 成功；1 输入/解码错误；2 用法错误；3 plan 文件错误。
```

### 2.1 decode 的六种形态

| 调用 | 行为 |
| --- | --- |
| `--plan F` | 按 plan 的槽位精确解码，槽位消费完后**必须**恰好用完所有位，多一位少一位都报错（退出码 1） |
| `--int64` | 每 64 位一个补码整数，十进制、带负号，**每行一个**；总位数不是 64 的倍数报错 |
| `--bytes` | 每 8 位一个字节，整体按 UTF-8 严格解码后输出（**不加结尾换行**）；不是 8 的倍数或 UTF-8 非法都报错 |
| `--hex` | 每 8 位一个字节，输出 `偏移: 十六进制（两位大写，空格分隔）  |可打印 ASCII|`，每行 16 字节，偏移从 0 起四位十六进制 |
| `--bits` | 原样位流，每 8 位一组用空格分隔，每行 8 组（=64 位）后换行，末行不加多余空格 |
| 无模式参数 | 猜模式并在 **stderr** 打一行说明：位数是 64 的倍数 → `--int64`；否则位数是 8 的倍数 → `--bytes`；否则 → `--bits`。stdout 只放结果 |

`--plan` 与其它模式参数同时出现 = 用法错误（退出码 2）。

### 2.2 encode

| 调用 | 行为 |
| --- | --- |
| `--int64` | 从输入读十进制整数（空白/换行分隔，允许负号），逐个输出 64 位补码位流；非法整数或超出 int64 范围（-2^63 .. 2^63-1）报错 |
| `--as-literal` | 在输出位流前加字面量前缀，便于粘进源码：文本模式 → `嘎嘎嘎嘎？<位流>`；`--int64` 模式 → `嘎嘎嘎？<该值的无符号二进制位串>`（负数在字面量模式下是错误：源码没有负数字面量，请用 `咕咕嘎咕？` 取负） |
| 无模式参数 | 把输入文本按 UTF-8 编码成字节位流（8 位/字节，高位在前），**不加结尾换行** |

encode 的输出恒为纯 `咕`/`嘎` 串（无空格无换行），可直接接管道。

## 3. plan 文件格式（宿主层 ASCII，行式）

```text
# 以 # 开头的行为注释；空行忽略
int64        # 64 位补码整数
bits <n>     # n 位位串（n 为正整数，原样输出）
bytes <n>    # n 个字节 = 8n 位，按 UTF-8 输出
bool         # 8 位布尔，输出 真 / 假
```

- 未知类型名、缺少参数、参数非正整数、多余记号 → 退出码 3，报出**行号**。
- `int64`/`bool`/`bytes` 在输出里各占一行；`bits <n>` 原样输出位串后换行。

## 5. 测试清单（每条都要有真实断言）

1. `bits.ts`：`咕嘎咕` → 值 2；`咕`×64 → 0；`嘎`×64 → -1（int64）；`300` → 低 64 位 = 300；负数 -2 → 64 位补码；空白容忍；非法字符报码点与下标。
2. `decode --int64`：320 位 → 5 个整数；非 64 倍数 → 错误。
3. `decode --bytes`：24 位 = `E5 97 A8` → `嗨`；多字节混合文本（ASCII + 中文 + emoji）round-trip；UTF-8 非法（如 `F0 FF FF`）→ 错误。
4. `decode --hex`：24 位 → `0000: E5 97 A8`；17 字节时正确换行。
5. `decode --bits`：`咕`×9 → `咕咕咕咕咕咕咕咕 咕`（按 8 位分组）。
6. plan：`bytes 3` 精确消费 24 位；`int64` 后剩余 8 位 → 报错（剩余位数出现在信息里）；plan 语法错 → 退出码 3 且带行号。
7. 无模式猜测三档：64 的倍数 → int64（stderr 有说明、stdout 只有数字）；8 的倍数 → bytes；都不是 → bits。
8. encode：`嗨` → 24 位位流（`E5 97 A8` 的每字节 8 位、高位在前，逐位断言）；`--as-literal` 前缀正确；`--int64` 负数与边界（-2^63、2^63-1、2^63 → 报错）。
9. CLI：`--help` → 0；无参数 → 2；未知子命令 → 2；`--plan` 与 `--bytes` 同给 → 2；文件不存在 → 2。
10. 端到端（子进程）：`../bin/gg.ts run ../examples/咕嘎咕嘎.咕咕` 的输出喂 `decode --bytes` → `嗨`；喂 `decode`（无模式）→ 也是 `嗨`；`printf 35 | ../bin/gg.ts run ../examples/咕嘎嘎咕.咕咕 | decode --plan plans/咕嘎嘎咕.plan` → 两行 `104` 与 `-2`。

本节由多方言任务书授权追加，**取代 §1 与 §2 中与之冲突的措辞**，§3–§6 不动。
SPEC.md §1 是权威：翻译器只是把同一套位名规则实现到输入解析与 encode 输出两侧。

### 7.1 输入的字符集（§1 的扩展）

位流输入按 SPEC.md §1.1 接受三种写法，**逐位置等价、同一份输入里可以混用**：

| 位 | 中文 | 日语 | 英语（ASCII，大小写不敏感） |
| --- | --- | --- | --- |
| 0 | 咕 U+5495 | グ U+30B0（兼容 ぐ U+3050） | 字母 g/G 后接 u/U，即 GU/Gu/gU/gu |
| 1 | 嘎 U+560E | ガ U+30AC（兼容 が U+304C） | 字母 g/G 后接 a/A，即 GA/Ga/gA/ga |

- 英文位名是**两个 ASCII 字母表示一位**，按对读取；配对之外的 g/G（例如行尾落单的 g）以及任何表外字符一律
  按 §1 的方式报错：`非法字符“x”（U+XXXX），位于输入第 N 个字符`，退出码 1。N 按**码点**计（emoji 算一个字符），
  英文位名占两个字符位。
- 空白：仍容忍空格、制表符、换行、回车，**另加 U+3000 全角空格**（SPEC.md §1.1 的日语缩进）。其它空白（如 U+00A0）仍非法。
- 内部一律归一化成 咕 / 嘎：plan 槽位、GGDIAG 帧、诊断正文都不受方言影响。

### 7.2 encode 的输出方言（§2 的扩展）

```text
用法：
  ggt decode [--plan <文件>] [--int64|--bytes|--hex|--bits] [<位流文件>]
  ggt decode --diag [<位流文件>]
  ggt encode [--int64|--as-literal] [--ja|--en] [<文本文件>]
  ggt --help
```

- 默认（不给开关）仍是 咕 / 嘎，输出与旧版逐字节相同。
- `--ja`：位名 グ / ガ，标点用全角（字面量前缀 `ガガガガ？`、`ガガガ？`）。
- `--en`：位名 GU / GA（每位两个字母，输出长度是位数的两倍），标点用半角（前缀 `GAGAGAGA?`、`GAGAGA?`）。
- `--ja` 与 `--en` 同时给 → 用法错误，退出码 2。两者只属于 encode；给 decode 或 `--diag` 会按未知选项报用法错误（退出码 2）。
- decode 与 `--diag` 的输出、plan 文件语义、GGDIAG v1 帧格式与码表：**一个字节都不变**。

### 7.3 `--diag` 接受三种方言的帧（task-33 追加）

外壳的位名字形跟源文件后缀走（SPEC.md §8.1），所以 stderr 上的诊断帧可能是 `咕`/`嘎`、`グ`/`ガ` 或 `GU`/`GA`。

- 解码器先用 §7.1 的归一化把输入变成 咕/嘎，再按 GGDIAG v1 过滤与解析；同一帧内逐位混排也接受。
- 帧结构、码表、输出排版（`行:列 码名 正文`，行列都为 0 时省前缀）、退出码 0/1/2/3 一律不变。
- `--diag` 仍不接受 `--ja`/`--en`（它们只属于 encode，给 decode 或 `--diag` 会按未知选项报用法错误，退出码 2）。
- 代价：宿主警告正文里若恰好出现 `gu`/`ga` 字母对，会被当成一个位——这是英语位名用 ASCII 的协议代价。
