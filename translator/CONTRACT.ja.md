# グガトランスレータ · 契約（凍結、変更はディスパッチャが行う）

本ファイルは**グガトランスレータ**プロジェクトのインターフェース契約です。トランスレータは「ググガガ語（中国語表記: 咕咕嘎嘎語）」の姉妹プロジェクトで、言語側は生のビットストリームを stdout に書くだけ、読みやすくするのは本プロジェクトの担当です。

## 0. 所在と分離

- 配置先ディレクトリ：`translator/`（リポジトリのルートからの相対パス。サンドボックスが本ワークスペースにしか書き込めないためここに置いているだけで、論理的には独立したプロジェクトです：独自の package.json / README / tests を持ちます）。
- 言語実装のどのモジュールも `import` しては**いけません**（`../src/**`、`../bin/**`）。唯一許される結合は、エンドツーエンドテストで**子プロセスとして** `../bin/gg.ts run ../examples/xxx.咕咕` を実行する場合だけです。
- 依存ゼロ：Node 組み込みモジュールだけを使います（`node:fs` / `node:process` / `node:path` / `node:test` / `node:assert`）。
- ソースは `.ts` で、Node の型ストリッピングで直接実行します（言語本体と同じ方式で、Node 24 で実測できることを確認済み）。

## 1. 入力の約束（言語側 README §4 より）

ビットストリームのテキストは二種類の文字だけを含みます：`咕`(0) と `嘎`(1)。デコーダは**空白を許容**します：スペース、`\t`、`\n`、`\r` は読み込み時に捨てます。それ以外の文字が現れたらエラー（終了コード 1）で、エラーメッセージはその文字と符号位置（`非法字符“x”（U+XXXX），位于输入第 N 个字符` の形）を報告しなければなりません。ここで N は、その文字が入力内で**1 から数えて何文字目か**（符号位置で数えます）です。

値のエンコード（デコード側は一つ残らず実装しなければなりません）：

| 型 | ビット幅 | エンコード |
| --- | --- | --- |
| 整数 int64 | 64 | 補数表現、上位ビットが先 |
| ビット列 bits(n) | n | そのまま、上位ビットが先 |
| バイト bytes(n) | 8n | 8 ビットごとに一バイト、上位ビットが先、全体を UTF-8 として解釈 |
| ブール bool | 8 | `咕` 8 個 = 偽、`嘎` 8 個 = 真 |

## 2. CLI 契約

```text
用法：
  ggt decode [--plan <文件>] [--int64|--bytes|--hex|--bits] [<位流文件>]
  ggt encode [--int64|--as-literal] [<文本文件>]
  ggt --help

未给 <文件> 时从 stdin 读；给出时从文件读。
退出码：0 成功；1 输入/解码错误；2 用法错误；3 plan 文件错误。
```

### 2.1 decode の六つの形態

| 呼び出し | 挙動 |
| --- | --- |
| `--plan F` | plan のスロットに従って正確にデコードし、スロットを使い切ったら**必ず**すべてのビットを使い切らなければならない。一ビットでも多い／少ないとエラー（終了コード 1） |
| `--int64` | 64 ビットごとに補数の整数、十進、負号付き、**一行に一つ**。総ビット数が 64 の倍数でなければエラー |
| `--bytes` | 8 ビットごとに一バイト、全体を UTF-8 として厳密にデコードしてから出力（**末尾の改行は付けない**）。8 の倍数でないか UTF-8 として不正ならエラー |
| `--hex` | 8 ビットごとに一バイト、`偏移: 十六进制（两位大写，空格分隔）  |可打印 ASCII|` の形で出力。各行 16 バイト、オフセットは 0 から四桁の十六進数 |
| `--bits` | ビットストリームをそのまま、8 ビットずつスペースで区切り、各行 8 組（= 64 ビット）ごとに改行、最終行に余分なスペースを付けない |
| モード指定なし | モードを推測し、**stderr** に一行の説明を出す：ビット数が 64 の倍数 → `--int64`；そうでなければビット数が 8 の倍数 → `--bytes`；どちらでもなければ → `--bits`。stdout には結果だけを置く |

`--plan` と他のモード指定を同時に与えるのは用法エラーです（終了コード 2）。

### 2.2 encode

| 呼び出し | 挙動 |
| --- | --- |
| `--int64` | 入力から十進整数を読む（空白／改行区切り、負号可）。一つずつ 64 ビットの補数ビットストリームとして出力する。不正な整数や int64 の範囲外（-2^63 .. 2^63-1）はエラー |
| `--as-literal` | 出力ビットストリームの前にリテラルの前置きを付けて、ソースにそのまま貼れるようにする：テキストモード → `嘎嘎嘎嘎？<位流>`；`--int64` モード → `嘎嘎嘎？<该值的无符号二进制位串>`（リテラルモードでの負数はエラー：ソースに負数のリテラルは無いので、`咕咕嘎咕？` で符号反転してください） |
| モード指定なし | 入力テキストを UTF-8 でバイト列のビットストリームにエンコードする（8 ビット／バイト、上位ビットが先）、**末尾の改行は付けない** |

encode の出力は常に `咕`/`嘎` だけの並びです（空白も改行もなし）。そのままパイプに繋げます。

## 3. plan ファイル形式（宿主層 ASCII、行指向）

```text
# 以 # 开头的行为注释；空行忽略
int64        # 64 位补码整数
bits <n>     # n 位位串（n 为正整数，原样输出）
bytes <n>    # n 个字节 = 8n 位，按 UTF-8 输出
bool         # 8 位布尔，输出 真 / 假
```

- 未知の型名、引数の欠落、引数が正整数でない、余分なトークン → 終了コード 3 で、**行番号**を報告します。
- `int64`/`bool`/`bytes` は出力でそれぞれ一行を占め、`bits <n>` はビットストリームをそのまま出力してから改行します。

## 5. テスト一覧（各項目に本物のアサーションを付けること）

1. `bits.ts`：`咕嘎咕` → 値 2；`咕`×64 → 0；`嘎`×64 → -1（int64）；`300` → 下位 64 ビット = 300；負数 -2 → 64 ビットの補数；空白の許容；不正文字は符号位置と文字位置を報告。
2. `decode --int64`：320 ビット → 5 個の整数；64 の倍数でない → エラー。
3. `decode --bytes`：24 ビット = `E5 97 A8` → `嗨`；マルチバイトの混在テキスト（ASCII + 中国語 + emoji）のラウンドトリップ；UTF-8 として不正（例 `F0 FF FF`）→ エラー。
4. `decode --hex`：24 ビット → `0000: E5 97 A8`；17 バイトのときに正しく折り返す。
5. `decode --bits`：`咕`×9 → `咕咕咕咕咕咕咕咕 咕`（8 ビットずつに区切る）。
6. plan：`bytes 3` は 24 ビットを正確に消費する；`int64` のあとに 8 ビット残る → エラー（残りビット数がメッセージに出る）；plan の構文エラー → 終了コード 3 で行番号付き。
7. モード指定なしの推測は三通り：64 の倍数 → int64（stderr に説明があり、stdout は数値だけ）；8 の倍数 → bytes；どちらでもない → bits。
8. encode：`嗨` → 24 ビットのビットストリーム（`E5 97 A8` の各バイト 8 ビット、上位ビットが先。ビット単位でアサートすること）；`--as-literal` の前置きが正しいこと；`--int64` の負数と境界（-2^63、2^63-1、2^63 → エラー）。
9. CLI：`--help` → 0；引数なし → 2；未知のサブコマンド → 2；`--plan` と `--bytes` を同時に与える → 2；ファイルが存在しない → 2。
10. エンドツーエンド（子プロセス）：`../bin/gg.ts run ../examples/咕嘎咕嘎.咕咕` の出力を `decode --bytes` に食わせる → `嗨`；`decode`（モード指定なし）に食わせる → これも `嗨`；`printf 35 | ../bin/gg.ts run ../examples/咕嘎嘎咕.咕咕 | decode --plan plans/咕嘎嘎咕.plan` → `104` と `-2` の二行。

### 7.1 入力の文字集合（§1 の拡張）

ビットストリーム入力は SPEC.md §1.1 の三つの書き方を受け付けます。**位置ごとに等価で、同じ入力の中では混ぜても構いません**：

| ビット | 中国語 | 日本語 | 英語（ASCII、大文字小文字を区別しない） |
| --- | --- | --- | --- |
| 0 | 咕 U+5495 | グ U+30B0（互換: ぐ U+3050） | 文字 g/G のあとに u/U、すなわち GU/Gu/gU/gu |
| 1 | 嘎 U+560E | ガ U+30AC（互換: が U+304C） | 文字 g/G のあとに a/A、すなわち GA/Ga/gA/ga |

- 英語のビット名は**二文字の ASCII で一ビット**を表し、対で読みます。対にならない g/G（たとえば行末に落ちた g）や表にない文字はすべて
  §1 の方式でエラーにします：`非法字符“x”（U+XXXX），位于输入第 N 个字符`、終了コード 1。N は**符号位置**で数えます（emoji も一文字）、
  英語のビット名は二文字分を占めます。
- 空白：スペース、タブ、改行、復帰を引き続き許容し、**さらに U+3000 の全角スペース**も許容します（SPEC.md §1.1 の日本語インデント）。その他の空白（たとえば U+00A0）は引き続き不正です。
- 内部では一律に 咕 / 嘎 に正規化します：plan のスロット、GGDIAG フレーム、診断本文は方言の影響を受けません。

### 7.2 encode の出力方言（§2 の拡張）

```text
用法：
  ggt decode [--plan <文件>] [--int64|--bytes|--hex|--bits] [<位流文件>]
  ggt decode --diag [<位流文件>]
  ggt encode [--int64|--as-literal] [--ja|--en] [<文本文件>]
  ggt --help
```

- 既定（スイッチなし）は引き続き 咕 / 嘎 で、出力は旧版とバイト単位で同じです。
- `--ja`：ビット名は グ / ガ、句読点は全角（リテラルの前置きは `ガガガガ？`、`ガガガ？`）。
- `--en`：ビット名は GU / GA（一ビットが二文字なので、出力の長さはビット数の二倍）、句読点は半角（前置きは `GAGAGAGA?`、`GAGAGA?`）。
- `--ja` と `--en` を同時に与える → 用法エラーで終了コード 2。両者は encode 専用で、decode や `--diag` に与えると未知のオプションとして用法エラーになります（終了コード 2）。
- decode と `--diag` の出力、plan ファイルの意味、GGDIAG v1 のフレーム形式と符号表：**一バイトも変えません**。
